# CARD-TEXT-AUDIT-1 — пригодность текстов карт для Text/Hybrid Policy

Ветка: `claude/card-text-audit-1` от `origin/main` `3f49efd`. Только аудит данных: encoder, `CardCatalog`/`CardFeatures`, Policy v1/v2, `StateEncoder`, checkpoint loader, скрипты Codex и pinned-файлы HearthstoneJSON не менялись, новые данные не скачивались.

Воспроизведение (read-only, ~1 с):

```bash
python -I scripts/audit_card_text.py --output <новый-файл>.json            # то, что закоммичено в summary.json
python -I scripts/audit_card_text.py --real-dir <data/processed_real> ...  # + счётчики card_id в локальных реальных данных
```

`summary.json` содержит все числа ниже (кроме раздела 2.9: он требует игнорируемых локальных данных и в тест воспроизводимости не входит). `tests/test_audit_card_text.py` проверяет, что чистый запуск совпадает с закоммиченным файлом. Нормализация внутри скрипта (`flat`) — аналитический инструмент для подсчёта дубликатов, **не** рекомендация для production-пайплайна.

## 1. Источник и идентичность

| Факт | Значение |
|---|---|
| Каталог | `data/cards/standard_current_enUS.json`, профиль `standard_full_20261001_v1`, `valid_as_of` 2026-10-01 |
| Snapshot | `data/cards/source_snapshots/cards_collectible_20261001_enUS.json`, 8170 карт (вся коллекционная база, включая Wild) |
| Хеш | `source_sha256` каталога = `d8c66168…b385a930` = sha256 файла snapshot (одинаков по сырым байтам и после CRLF→LF) |
| Записи каталога | все 1185 записей равны (по JSON) записям snapshot с тем же `id`, т. е. каталог — выборка, а не пересчёт |
| Уникальность | 1185 уникальных `id`, 1185 уникальных `dbfId`, 1185 уникальных `name` в Standard |
| Номер сборки игры | **не записан** ни в каталоге, ни в snapshot (только `valid_as_of` и хеш). Источник — `…/v1/latest/…`, т. е. текст зафиксирован снимком на 2026-10-01 и может расходиться с живым клиентом после баланс-патча |

Привязка текста к `card_id` однозначна **внутри Standard-каталога**. Опасности вне его:

- Префикс Core записан в двух регистрах: `CORE_…` (264) и `Core_…` (3, например `Core_CS2_200`). Любое сопоставление по строке без учёта регистра или по «отрезанию префикса» ненадёжно.
- В полном snapshot **1272 имени из 6654 принадлежат нескольким ID**; 259 из 267 Core-карт Standard имеют одноимённый ID в другом наборе. Привязка «имя в тексте → карта» (`add an 'Arcane Missiles' spell`; в Standard-каталоге такого ID нет, в snapshot их два) однозначной не бывает.
- 25 записей без `cardClass` имеют вместо него список `classes` (3 CATA-героя/миньона и 22 `END_*`). Для `CardCatalog` это `UNKNOWN_CLASS`, не имеющее отношения к тексту, но они же — самые «нестандартные» по тексту.

### 2.3 Сегменты через `@` и «1»

16 карт содержат несколько сегментов в одной строке `text`; `@` здесь играет разные роли, так что это **не** один формат:

- **A. Полные варианты** (4 карты: CATA_131, CATA_132, CATA_140, CATA_190h): `…({0} left!)@…(Ready!)@…без счётчика`. У CATA_190h варианты различаются и содержательно (`twice`/`once to upgrade`).
- **B. Основной текст + фрагменты прогресса** (3 карты: EDR_430, JAIL_735, TIME_005): после первого сегмента идут ` <i>({0} left!)</i>` и ` <i>(Ready!)</i>`, самостоятельного правила в них нет.
- **C. Слот динамического числа** (6 карт: END_009, JAIL_474, JAIL_909, JAIL_974, TIME_048, TIME_103): сегменты ` <i>(` и `)</i>`, `/4)</i>`, ` turns)</i>`, ` cards)</i>` — по форме `(@)`, `(@/4)`, `(@ turns)`, т. е. `@` стоит на месте числа.
- **D. Литеральная `1` вместо `@`** (3 карты: FIR_911/914/916): `…!)</i>1Draw {0} cards.` — два варианта, склеенных цифрой. Видимо, потерянный управляющий символ; в snapshot это буквально `1`, токенизатор породит слова `1deal`, `1draw`, `1give`.

Классификация A–D выведена только из формы строк, не из документации формата. Итого 4 + 3 + 6 + 3 = 16 карт.

`collectionText` есть у 24 карт. У 12 из 13 карт с `@` (кроме CATA_190h) он **дословно равен первому сегменту** — это единственный проверяемый по данным признак «базового» сегмента. Для CATA_190h он совпадает с вторым сегментом по смыслу, но не дословно. У ещё 10 карт (CATA_134, CATA_479, CATA_489, CATA_550, CATA_614, EDR_950, MEND_500/502/504) `collectionText` — **другая формулировка**, не подстрока `text` (например, CATA_134 без слова `Shatter`), так что подменять им `text` нельзя. Для FIR_911/914/916 `collectionText` нет. Итого: правило «первый сегмент = базовый» подтверждается для 12 карт и не проверяемо для остальных 4.

### 2.4 Расхождения `text` и `mechanics`

- **Ведущее ключевое слово совпадает с тегом**: у 511 миньонов с ключевым словом в начале текста (`Taunt`, `Battlecry:`…) нет ни одного без соответствующего тега. Этого достаточно, чтобы доверять тегу как проверке, но не наоборот.
- **Тег есть, слова нет** (3 карты): CATA_206 (`TAUNT`, `ELUSIVE` скрыты за `{0}, {1}`), JAIL_397/JAIL_430 (`START_OF_GAME_KEYWORD`: текст описывает построение колоды, слова «Start of Game» нет).
- **Слово жирным без тега** — десятки карт, но это в основном **упоминания, а не свойства**: `Give a minion … Taunt`, `Discover a Battlecry minion`, `Scaled Lancer: All enemy minions have Taunt`. По одному тексту «жирное слово = свойство карты» выводить нельзя.
- **Ключевые слова без тега в `mechanics` вообще**: Kindred (29 карт), Corpses (25), Prepare (20), Dark Gift (20), Imbue (19), Rewind (19), Dormant (17), Herald (15), Fabled (11), Shatter (7), Reward (13). 194 карты содержат хотя бы одно такое слово. Именно здесь текст несёт то, чего нет в структурных признаках (аргумент **за** Text), но смысл слова в данных не определён (аргумент **за** осторожность: модель получает токен без правил).
- `TRIGGER_VISUAL` (155 карт) — по названию тег отображения триггера, а не ключевое слово: одноимённого слова в тексте нет. Использовать его как «ключевое слово» не следует.

### 2.5 Дубликаты

- Точные дубликаты нормализованного текста: **8 групп / 19 карт**, все — ключевые слова или короткие правила (`Taunt` ×2, `Stealth` ×3, `Lifesteal` ×3, `Elusive` ×3, `Taunt Divine Shield`, `After your hero attacks, draw a card.` ×2, `Battlecry: Imbue your Hero Power.` ×2, `Taunt Battlecry: Herald {0}.` ×2). Разные ID, разные статы.
- После замены чисел на `N`: **13 групп / 30 карт** (шаблонные семьи).
- Функциональных клонов (текст + тип + стоимость + статы) внутри Standard: **0**.
- Ближайший другой текст по триграммам слов (Jaccard): у 8 карт 0,7–0,9, у 66 карт 0,5–0,7, у остальных ниже; медиана 0,21; ≥ 0,9 без точного совпадения — 0. Внутри Standard тексты в основном разные.
- **Но вне Standard**: из 6985 карт snapshot вне каталога 6157 имеют текст; **460** дословно совпадают с текстом карты Standard, и **313** — полные функциональные близнецы (текст + тип + стоимость + статы + класс), как правило это оригиналы Core-карт. Это важно для любого split «unseen cards» (раздел 5).

### 2.6 Слова, выдающие карту

Словарь нормализованных текстов — 789 слов. 362 слова встречаются ровно в одной карте; **252 карты (21 %)** содержат слово, уникальное для неё, **333 (28 %)** — слово, встречающееся не более чем у двух. 7 текстов содержат имя самой карты (`Wickerfang's Legs`, `Timelooper Toki`: CATA_139, CATA_185, CATA_586, EDR_465, EDR_978, JAIL_906, TIME_861), 19 называют другую карту каталога (грубо: подстрока имени длиной ≥ 8). Для модели с обучаемым вектором текста это готовый «ID-ключ».

### 2.7 Длина

Нормализованный текст: медиана 12 слов / 65 символов, p99 = 23 слова / 117 символов, максимум 57 слов / 329 символов (это HERO CATA_190h с тремя сегментами). Это длина в словах; число subword-токенов зависит от encoder и не измерялось. У карт с сегментами длина завышена примерно в 2–3 раза относительно одного варианта.

### 2.8 Что встречается в формулировках

Грубые поверхностные шаблоны (число карт, текст может попасть в несколько): damage 202, summon 212, random 230, give stats 169, cost change 135, draw 130, «this game/this turn/history» 129, trigger «whenever/after» 105, discover 90, aura-like («while/has/all friendly|enemy») 87, `if` 137, choose 61, copy 53, destroy 58, start/end of turn 63, for each 37, restore 29, quoted granted text (`give your minions "Deathrattle: …"`) 28, opponent hand/deck 26, shuffle 25, transform 16. Это счёт слов, а не таксономия правил и не вывод о реализации.

## 4. Рекомендации по обработке текста (для Codex)

Это рекомендации по результатам аудита, не реализация encoder.

**Что удалять**

- `[x]` (527 карт), `\n` и nbsp как layout: заменять одним пробелом; `\n` посреди фразы — не граница предложения.
- Теги `<b>…</b>`, `<i>…</i>` — **только после** решения, что их заменяет (см. ниже). Регистр тега не доверять (`</I>`), вложенные теги разворачивать (`<b><b>X</b>.</b>`).
- Поля `flavor`, `howToEarn*`, `artist`, `collectionText` — не правило, в текстовую подачу не входят.

**Что обязательно сохранять**

- Границы ключевых слов: `Taunt Battlecry: Deal 4 damage.` после снятия тегов неотличимо от обычных слов. Рекомендация — заменять `<b>X</b>` явным маркером ключевого слова (отдельный токен/признак), а не просто стирать.
- Содержимое курсива. 66 карт содержат 55 различных курсивных фраз; среди них и правила (`While in hand, play a Dragon to become an 8/8 Dragon!`, `Cast 3 spells to gain Lifesteal.`, `20% chance to take 5 damage each refresh!`, `They keep their original stats and Cost.`), и счётчики (`{0} left!`, `Ready!`). Удалять курсив целиком нельзя; отделять счётчики от правил — только по явному списку.
- Числа и их маркеры: `$N`/`#N` (число + признак «урон/лечение»), `(N)` (буквальный текст со стоимостью/порогом), `+N/+N`, `N-Cost`. Числа в тексте — **базовые**.
- Структура `Choose One - A; or B`, `Quest: … Reward: …`, `Battlecry and Deathrattle:`.
- Кавычки внутри правила (`give your minions "Deathrattle: …"` — вложенная способность, не триггер самой карты).

**Отсутствие текста**: хранить явный флаг «текст отсутствует» (маска), а не пустой вектор, неотличимый от «нет эффекта». Не писать «vanilla»: источник этого не утверждает. Значение признака не должно участвовать в сравнении «текстовая карта лучше нетекстовой».

**Неизвестные card_id**: не бросать исключение и не придумывать текст; те же правила, что у `CardCatalog.get` для структуры (property-light запись), плюс флаг «текста нет». Из 508 реальных ID 122 нет нигде; для 11 есть текст в snapshot, но подключать его надо как отдельный явный источник с отдельной записью в checkpoint, не расширяя словарь обученных индексов ID. Не создавать ID по имени из текста.

**Базовый текст vs текущие характеристики**: текст — свойство **класса** карты (`card_id`), одинаковое для всех экземпляров. Текущая стоимость, статы, прочность, счётчики, прогресс, Dark Gift, состояние превращений — признаки экземпляра (`current_*`, `trigger_remaining`…) и остаются отдельными каналами. Числа в тексте не пересчитывать «в текущие». Не подставлять значения вместо `{0}`/`@`.

**Не смешивать identity / name / flavor / rule text**: отдельные поля и отдельные входы; имя карты — не часть правила. Проверять отсутствие `name`/`flavor` в тексте входа тестом на уровне схемы. Если имя карты встречается внутри её собственного `text` (7 случаев), заменять на нейтральный токен «эта карта» **в обоих сравниваемых вариантах** одинаково.

**Версия источника**: записывать в checkpoint/датасет `profile_id`, `valid_as_of`, `source_sha256`, число карт, версию правил нормализации и хеш получившегося словаря текстов. Учесть, что номер сборки игры в данных отсутствует: при смене snapshot старый checkpoint должен отказываться, а не молча брать новые тексты.

**Не нормализовать автоматически**

1. Выбор базового сегмента при `@`/`1` (раздел 2.3): четыре схемы, 16 карт — таблица решений вручную; `collectionText` подтверждает первый сегмент лишь у 12.
2. Подстановка и удаление `{0}`/`{1}`/`@`: значение неизвестно, а `Herald {0}` без значения всё равно часть правила.
3. Склонение `|4(a,b)` — выбор формы зависит от числа, которого нет.
4. Курсив: правило против счётчика.
5. Привязка упоминаний по имени (`'Arcane Missiles'`, `Cannoneers`, `Cubs`, `Treants`) к `card_id` — неоднозначна и часто невозможна.
6. Ключевые слова без определения в данных (Herald, Imbue, Kindred, Dark Gift, Rewind, Prepare, Dormant, Shatter, Fabled): токен можно сохранить, но значение вывести нельзя.
7. «Жирное слово = свойство» и «нет тега = нет свойства» — оба неверны (раздел 2.4).
8. Регистр ID: `Core_` ≠ `CORE_` по строке; не склеивать префиксы без списка.

## 6. Итоговые ответы

**1. Насколько готов каталог?** Данные в Standard-каталоге достаточны: полный охват (1182/1185), однозначная привязка, чистый хеш-pin. Не готов **путь к модели**: нет места, где текст хранится рядом с `CardFeatures`/checkpoint, нет нормализатора и нет источника для токенов/hero power/Монеты, которые составляют заметную долю реальных состояний.

**2. Критичные проблемы.**
1. До 15–30 % сущностей в реальных состояниях (токены, Монета, hero power) без текста в имеющихся данных.
2. Контрольный набор MODEL-FIRST-1 использует одну реальную карту `BE_036` как заглушку почти для всех миньонов и содержит только атаки и конец хода; пользу текста на нём измерить нельзя, а Text-вариант получит постоянный посторонний текст.
3. `@`/`1`-сегменты и `{0}` — не разбираются автоматически (16+32 карты).
4. Риск утечки «уникальные слова/близнецы» при split по `card_id` (раздел 5).
5. Нет номера сборки; тексты прикреплены к снимку 2026-10-01.

**3. Обязательные нормализации.** `[x]`, nbsp, layout `\n` → пробел; разбор регистра/вложенности тегов; bold → явный маркер ключевого слова; курсив сохранять (правила внутри); `$N`/`#N` → число + признак; плейсхолдеры `{n}`, `@` оставлять как явные слоты без подстановки; сегменты `@`/`1` — по таблице по карте; флаг «текст отсутствует»; фиксировать версию правил и хеш источника.

**4. Типичные ошибки Codex при Text/Hybrid.** Стирать теги и получать неотличимые «Taunt Battlecry: Deal»; удалять курсив с правилами; подставлять `0` или имя вместо `{0}`; брать первый сегмент `@` как «базовый» или токенизировать `1deal`; считать жирное слово свойством карты (Scaled Lancer, Blazing Invocation); читать `text` как современную стоимость/статы (Medivh's Triumph, Ravenous Felfisher); класть текст внутрь `CardFeatures`/словаря ID и тем самым менять обученные индексы; считать пустой текст «нет эффектов»; нормализовать `Core_`/`CORE_` склейкой; делить «unseen» по `card_id`, оставляя Core-близнецов в train; не заметить, что у токенов и hero power текста нет.

## 7. Ограничения аудита

- Все счётчики реальных данных — из 36 локальных файлов main checkout (на момент аудита) и не воспроизводятся из чистого checkout; значения повторяются по позициям.
- Смысл ключевых слов Dark Gift, Herald, Imbue и др., формат-соглашения `$`/`#`, роль `@` выведены из формы строк и общих сведений о формате, а не из документации в репозитории; такие места помечены в тексте.
- Не проверялось, соответствуют ли тексты живому клиенту: сравнить без новых данных нельзя.
- Не выполнялось обучение, evaluation, simulator-проверки и правки каталога. Замороженный control читался только на уровне структуры (ID карт, типы действий), метки и результаты не анализировались.
