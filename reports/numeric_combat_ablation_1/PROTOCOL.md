# NUMERIC-COMBAT-ABLATION-1: до fits

2026-10-11. Зависимость: TL2 `6abb978`, поверх TL1 `a3b9b9d`; main `2a661089`. Никаких merge/rebase. H: явные обычные kill/survive и маски известности улучшат counterfactual source selection. Baseline A — v2 на real+tactical, B — те же данные с четырьмя изолированными колонками. Исходный checkpoint обоих: SHA `d2f18737be46bc1773997ec5106d1e30fdf2caaf645a3a7c8998956f092d6377`.

Четыре бинарных значения: target_destroyed, target_destroyed_known, source_survives, source_survives_known. Для известного обычного minion→minion боя учитываются положительный Attack, Health, Divine Shield, Poisonous, Immune, строгое survival HP>retaliation. Для неизвестного текста, реактивных механик, секретов, Locations, active effects, evidence constraints или неизвестных relevant flags — значения/маски нули. Hero/non-attack — нули. Это локальные свойства заданного боя без внешних реакций, не стратегическая ценность или предсказание полной позиции. Никаких Outcome after-states, gold или certificate goal в input; только состояние и доступная card metadata. TL2 synthetic text declarations — явно заданная metadata, не label.

Production Policy/encoder/schema/dispatch неизменны. B — изолированный subclass с четырьмя новыми колонками action projection, 256 новых весов при hidden64; новые колонки нулевые, общие веса копируются. Ни ручной прибавки к score, ни predetermined предпочтения. Общие параметры обучаются вместе с новыми тем же AdamW LR. Checkpoint B — отдельная experimental schema с проверенными feature order, metadata digest и companion base.pt; production loader отвергает её.

Оба кандидата получают одинаковые примеры и порядок: TL2 validated train192/validation32 без изменений; прежний whole-match real train32/1175 и validation7/281; 1280 real+320 tactical за эпоху, одинаковый Stream seed42 и dropout seed каждого шага. Одинаковый set loss, AdamW LR0.0001 WD0.001 clipping1, batch32, 50 steps/epoch, ≤12 epochs и ≤600 seconds CUDA на кандидата. Ровно два fits; никаких optimizer smoke tests. Общая early stop patience4.

Selection: минимальная tactical validation CE при real CE≤initial+0.03 и Top1≥initial−0.03; fallback min real CE с failed guard. Остановка при отсутствии допустимого улучшения четыре эпохи у любого кандидата. Control integrity проверяется до optimizers, но не ранжируется моделями до сохранения обоих checkpoints.

Новый control64: 8 base stats-пар (4 Attack,4 Health), их 8 position и 8 unknown-ID пар, 8 сертифицированных single lethal и 8 unlabelled metadata-unavailable случаев. Пять/шесть/семь источников и три Taunt, два со щитом, отличаются от раскрытых контролей TL1/TL2/MF1/MF2C. Численные пары меняют только текущие значения двух источников и связанные descriptors, сохраняя card IDs/позиции/metadata. Unknown-ID variants сохраняют явно объявленную vanilla metadata; unlabelled unavailable-context cases отключают её доступность для experimental extractor и не получают gold. Проверяются целые menus и independent arithmetic vs exact Outcome. Проверка нормализованных клонов всех четырёх раскрытых контролей обязательна; сама по себе она не доказывает полную независимость от общих правил боя.

GO: ≥4/8 base pairs с двумя верными ответами и правильной сменой источника, преимущество ≥2 пары над A, ≥4/8 таких пар в каждом из position и unknown-ID вариантов; real B CE≤min(A,initial)+0.05 и Top1≥max(A,initial)−0.03; ноль новых lethal ошибок против A, frozen и TL2 B на новом control; оба selection guards. NO-GO при serious real/lethal regression или отсутствии base stats gain; смешанные результаты — INCONCLUSIVE. GO разрешает только независимую проверку, не LIVE, не утверждение роста real win rate.

После двух selected saves новый контроль открывается ровно один раз. Дополнительно сравниваются frozen, initial, TL2 A/B на нём, а старый TL2 control используется только как раскрытая regression diagnostic после selection. Posthoc numeric-zero ablation и logit differences вычисляются для выбранного B без обучения. Публично код/агрегаты/истории/manifest, приватные inputs и все checkpoints сохраняются ignored. Bootstrap real uncertainty по целым validation матчам, не отдельным позициям. После открытия контроля не меняем представление или конфигурацию и не выбираем другую эпоху.
