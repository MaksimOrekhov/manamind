# ML-EVAL-0 — оценка качества real Policy

Дата: 2026-10-08
Основа: `origin/main` `9708e70b557d111591f0db486486ba450d47408f`
Режим: аудит существующих артефактов и inference; **нового обучения и подбора параметров не было**.

## Вывод

Обе модели ранжируют последующее человеческое действие лучше аналитического uniform baseline на матчах, не входивших по `game_id` ни в один сохранённый ML-1C/ML-2A split. На общей выборке v2 улучшила все четыре метрики относительно v1. Это предварительный поведенческий сигнал на 12 матчах одного SELF-класса, а не доказательство силы игры или оптимальности человеческих действий. Текущую локальную коллекцию нельзя напрямую открыть строгим `load_examples`: её состояния предшествуют добавлению двух сериализуемых `healing_bonus: null` полей. Для оценки использовалась только временная in-memory нормализация с проверкой исходных state hash; файлы данных не менялись. Перед следующим обучением коллекцию нужно заново экспортировать текущим ML-1B pipeline.

V1 кодирует общие признаки состояния, суммарный board context и легальные действия, но не представляет каждую видимую board entity с её identity и связями. V2 добавляет видимые токены сущностей с текущими статами/статусами, ролью и позицией, embeddings source/target и связи candidate action с source, target и соседями insertion slot. Обе версии соблюдают границу видимости: hidden hand/deck/order/opponent identity не кодируются.

## Сравнение на общей выборке вне frozen splits

Выборка — **12 матчей / 515 решений** текущей коллекции, у которых `game_id` не входит ни в train, validation, ни в test ML-1C/ML-2A. Она была одинаковой для обеих моделей и не использовалась для обучения или настройки. Все 12 матчей — SELF Priest; это ограничивает переносимость вывода. Top-3 вычисляется только на меню из 3+ действий (421 решение). Uniform — аналитический равновероятный выбор среди полного legal menu.

| Ранжировщик | CE ↓ | Top-1 | Top-3 | MRR |
|---|---:|---:|---:|---:|
| Uniform expected | 2.0285 | 0.2349 | 0.3488 | 0.4048 |
| ML-1C v1 | 1.7519 | 0.5146 | 0.6200 | 0.6378 |
| ML-2A v2 | **1.5340** | **0.5476** | **0.6698** | **0.6696** |

Среди решений с нетривиальным меню (465) top-1 составил 0.462 v1 и 0.499 v2; CE — 1.940 и 1.699 соответственно. По отдельным матчам exact top-1 колебался: v1 от 0.36 до 0.77, v2 от 0.36 до 0.87. Поэтому 515 зависимых decision states нельзя считать 515 независимыми наблюдениями.

Разрезы указывают на конкретные слабости:

- В 113/515 меню есть target. Exact top-1 на них — 0.195 v1 и 0.212 v2 (MRR 0.356 и 0.394). Без target это 0.604 и 0.642. Точная разница между целями остаётся тяжёлой даже с v2 target embedding.
- PLAY_CARD составляет 255 решений; exact top-1 — 0.369 v1 и 0.404 v2. ACTIVATE_LOCATION — 20 решений; соответственно 0/20 и 3/20. Малые подмножества не позволяют обобщать, но подтверждают, что общая точность скрывает типы действий с плохим ранжированием.
- В 403 решениях рука содержит UNK. Их top-1 ниже, чем у строк без UNK: 0.499/0.524 против 0.571/0.634. Для 90 выбранных UNK действий v1/v2 дают 0.433/0.533. UNK — заметная граница представления, но имеющиеся разрезы не показывают, что он доминирует над ошибками target/action.
- У выбранных действий нет точных input-encoding collisions. Значит, наблюдаемые ошибки не сводятся к двум разным legal actions с идентичным закодированным вектором.
- В свежей по split выборке все решения Priest. Исторический корпус содержал 18 Priest и 3 Warrior матча; validation/test также были очень малы. Полные deck identity не восстанавливались, а видимые карты в руке не считаются достоверным архетипом.

## Train/validation/test и переобучение

Исторические метрики ниже — воспроизведённая оценка из сохранённых ML-1C/ML-2A артефактов на тех же 21 матчах; test уже использовался в ML-1C/ML-2A и здесь не участвовал в выборе. Новый inference-аудит также проверил обе модели на test: численные результаты совпали с опубликованными с погрешностью округления. Для будущего выбора моделей эти два test матча нельзя считать нетронутыми.

| Split / метрика | v1 | v2 |
|---|---:|---:|
| Train CE / top-1 / top-3 / MRR | 1.1787 / .631 / .768 / .7456 | 1.3775 / .609 / .716 / .7176 |
| Validation CE / top-1 / top-3 / MRR | 1.8829 / .471 / .575 / .5923 | 1.6815 / .518 / .644 / .6352 |
| Test CE / top-1 / top-3 / MRR | 1.7900 / .467 / .571 / .5938 | 1.8225 / .450 / .714 / .6158 |

В прежних training histories v1 train CE снижался 1.760 → 1.179 → 0.549 на эпохах 1/6/14, тогда как validation после минимума 1.883 вернулся к 2.072 к остановке на epoch 14. У v2 train CE продолжал снижаться 1.692 → 1.378 → 1.168 на эпохах 1/8/16; validation достиг 1.681 на epoch 8 и вырос до 1.819 к остановке на epoch 16. Это прямое свидетельство overfitting у обеих версий. Checkpoint-и сохраняли validation-selected эпохи 6 и 8. На test v2 повысил top-3/MRR, но уступил v1 по CE/top-1; сравнение не оправдывает замену default v1 на v2.

## Readiness и следующий шаг

Текущий PolicyNetworkV2 технически достаточен для ограниченного read-only live recommendation: checkpoint контракт строгий, v2 inference поддерживается, а default остаётся проверенным v1. Эта оценка не является разрешением включать v2 по умолчанию и не означает игровую силу.

Для нового обучения текущая собранная папка сначала должна пройти **не нормализацию в файлах, а штатный ML-1B rebuild**: прямой `load_examples` сейчас fail-closed. Даже после rebuild объём и одно-классовая свежая выборка недостаточны для вывода о переносе между классами/колодами. Unknown и target slices также слишком малы для причинных выводов. Чекпойнты, код live или схемы в этой задаче не менялись.

**Рекомендуемая следующая задача: `ML-DATA-REFRESH-1 — Canonical real-policy holdout`.** Повторно экспортировать доступные Power.log через текущий ML-1B pipeline, добиться прямого прохождения `audit_dataset/load_examples`, добавить матчи с SELF-классами помимо Priest, затем заморозить новые whole-game validation/test группы с проверенной непересекаемостью. На untouched holdout сначала сравнить только закреплённые v1/v2 checkpoint-и и action/target slices; не обучать и не выбирать модель до фиксации состава и границ нового holdout. После этого можно решать, нужен ли новый supervised run.

## Параметры сохранённых экспериментов

Эта оценка не подбирала и не меняла параметры. Исторические v1/v2 runs использовали seed и split seed 42, детерминированный CPU, один Torch thread, AdamW learning rate 0.001 и weight decay 0.001, batch 32, gradient clip 1, максимум 60 эпох, patience 8 и min_delta 0.0001. V1: hidden 128, выбран epoch 6, остановка epoch 14. V2: hidden 64, dropout 0.1, выбран epoch 8, остановка epoch 16. Dataset, split и config hashes записаны в исходных ML-1C/ML-2A отчётах; здесь checkpoint-и только загружались и оценивались.

## Пять приоритетных ограничений

Порядок отражает практические препятствия следующей итерации, а не доказанный причинный вклад в ошибки:

1. **Мало независимых матчей и классов.** Новый по split срез содержит 12 матчей, все Priest; решения одного матча коррелируют.
2. **Есть свидетельство переобучения.** Train CE продолжал падать после выбранной по validation эпохи у обеих моделей.
3. **Точный выбор цели остаётся слабым.** На 113 targeted decisions top-1 около 0.20 у обеих моделей; PLAY_CARD также ниже общей точности.
4. **Много неизвестных карт в видимой руке.** В 403/515 решений есть неизвестная карта SELF hand, но метрики не доказывают, что UNK — основная причина ошибок.
5. **Текущая коллекция не проходит canonical loader напрямую.** Перед новым обучением нужен штатный rebuild текущим ML-1B exporter; временная нормализация была только для inference-аудита.
