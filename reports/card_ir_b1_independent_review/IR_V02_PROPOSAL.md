# Card IR v0.2 — минимальное предложение по итогам независимого аудита B1

**Статус:** проект. Ничего из этого не реализовано: код Card IR, словарь, валидатор и декларации A/B1 не менялись.
**Основание:** [CARD_AUDIT.md](CARD_AUDIT.md), [INDEPENDENT_INTERPRETATION.md](INDEPENDENT_INTERPRETATION.md),
[diagnostics.json](diagnostics.json).
**Автор:** Claude Opus 5.5 (модельное ревью, не gold).

## 1. Принципы отбора

1. **Сначала композиция.** Пробел признаётся, только если его нельзя выразить существующими элементами. В B1 два
   первичных PARTIAL (V'ama, Nascent Bolt) и две вторичные причины (split у Magma Hound, токен у Imp) снимаются без
   изменения языка.
2. **Правило раньше операции.** Если перемещение уже выражено, а не определено его поведение, добавляется универсальное
   правило `R_*`, а не новая операция (Waggle Pick).
3. **Параметр раньше структуры.** Новое значение перечисления, поле или роль у существующего элемента дешевле нового
   вида узла: один валидатор, одна ветка исполнителя, без новых форм композиции.
4. **Общность проверяется частотой.** Для каждого кандидата приведён текстовый экран по рамке B1 (1 276 карт,
   `diagnostics.json → reuse`). Экран считает упоминания, а не семантику; это порядок величины, не доказательство.
5. **Неизвестное остаётся явным.** Ни одно изменение не должно превращать UNKNOWN в правдоподобное значение.

## 2. Предложения Codex: решение по каждому

| Предложение B1 | Решение | Почему |
|---|---|---|
| `control:SCHEDULE` (структура) | **отклонить** → E5 | достаточно параметра отложенного старта у `ADD_PLAYER_EFFECT`; планировщик общего вида шире любой карты B1 и плохо определён |
| `keyword:LUNAR_CYCLE` | **отклонить** | фактически карточный элемент: «лунный цикл» есть только у Aviana |
| `duration:THIS_GAME` | **принять** (E4) | постоянный эффект игрока |
| `cond:NOT` (структура) | **отклонить** | отрицание множества уже есть: `exclude` (проверено валидатором). Вернуться, если понадобится отрицание **условия**, а не множества |
| `pred:SURVIVES` | **принять как `alive`** (E1) | общее имя; то же нужно для «if it dies», «survives» у существ |
| `keyword:HERALD` | **отложить** (E11) | без правила Herald, формулы `{1}` и данных о Deathwing Ultraxion всё равно останется PARTIAL |
| `counter:SPELL_DAMAGE_DEALT` | **обобщить** (E7) | счётчик `DAMAGE_DEALT` с агрегацией суммы и предикатами источника; узкий enum не нужен |
| `op:INSERT_INTO_DECK` (структура) + `count`, `position`, `BOTTOM` | **заменить параметрами** (E9) | позиция и количество — параметры существующей вставки в колоду, новая операция не нужна |
| `duration:NEXT_OPPONENT_TURN` | **обобщить** (E3) | `NEXT_TURN` затронутого игрока; то же нужно для «your next turn» |
| `op:RETURN_TO_HAND` (структура) | **отклонить** → R1 (+S2 для Torch) | перемещение PLAY→HAND уже есть (`ADD_TO_HAND` + `from_zone`); не хватает правила сброса и полной руки |
| `event:SOURCE_ATTACK`, `pred:SURVIVES` для Magma Hound | **заменить ролью** (E2) + E1 | у `ATTACK_DECLARED` уже есть `defender` и тайминг `AFTER`; нужна определённая роль `attacker` |
| `value:EXCESS_DAMAGE` (структура) | **не нужно для B1** | у Torch excess выражается арифметикой v0.1 (`set`/`stat`/`sub`/`max`), как у BE_555 в A; общий `damage_result` — кандидат на будущее для карт с `$`-усиленным excess |
| `op:FREEZE` (структура) | **принять** (S1) | Frozen — состояние со своим правилом снятия; встречается часто; был в списке пробелов пилота A |

Итого из 6 структурных предложений Codex реально нужна **одна** операция (FREEZE). Ещё один структурный механизм
(параметр экземпляра, S2) нужен Torch, но Codex его не назвал. Из 8 перечислений 5 принимаются в обобщённом виде
(`THIS_GAME`, `alive`, `DAMAGE_DEALT/AMOUNT`, `BOTTOM` как значение `position`, `NEXT_TURN`), 1 заменяется ролью у
существующего события (`SOURCE_ATTACK` → `attacker`), 1 отклоняется (`LUNAR_CYCLE`), 1 откладывается (`HERALD`). Оба
параметра (`count`, `position`) принимаются, но для существующей операции вставки в колоду.

## 3. Минимальный набор v0.2

### 3.0 Уровень 0 — без новых элементов языка

**Процесс авторства.** Перед тем как объявить пробел, автор обязан пройти чек-лист композиций и записать, почему он не
подошёл: отрицание → `exclude`; «split» → `repeat` + `RANDOM` + удар 1; «survives» → `if` + `alive` (до E1 —
`cmp HEALTH > 0`); excess → `set`/`stat`/`sub`/`max`; «it/them» → `as`/`ref`; токен → поиск по префиксу ID и статам.

**Универсальные правила** (новые или переведённые из UNKNOWN; основание — `COMMUNITY_RULES` с цитатой wiki, пока не
подтверждено логами):

| ID | Правило | Источник | Нужно картам B1 |
|---|---|---|---|
| R1 `R_RETURN_TO_HAND` | Перемещение PLAY→HAND даёт исходную карту: урон, зачарования и Silence снимаются, трансформации остаются. При 10 картах в руке существо уничтожается и **умирает** (Deathrattle, death-триггеры); последующие шаги про «it» ничего не делают | wiki «Return to hand» | Waggle Pick, Torch (возврат себя) |
| R2 `R_SPLIT` | «Split among X» без «randomly» = «randomly split»: серия ударов по 1, цель каждого выбирается среди живых, смертельно раненые исключаются, Immune и Stealth допустимы | wiki «Damage», «Arcane Missiles» | Magma Hound |
| R3 `R_SURVIVE` | «Выжил» = после реакций шага и до Death Phase сущность в игре, Health > 0 и не помечена на уничтожение | wiki «Slam» (notes) | Nascent Bolt, Magma Hound |
| R4 `R_COST` (обновить) | Модификаторы применяются в порядке создания; `set` перекрывает более старые, более новые действуют поверх; минимум 0 — после всех; самомодификатор стоимости действует только в руке | wiki «Mana cost», «Aviana, Elune's Chosen», «Loatheb» | Aviana, Spellweaver's, Cult Neophyte, Waggle Pick |
| R5 `R_PLAYER_EFFECT` (обновить) | Эффект игрока висит на игроке и не зависит от источника. С `uses` — действует на следующие N подходящих карт/эффектов; **без `uses` — на все подходящие карты в течение длительности**, включая пришедшие позже | wiki «Loatheb» | Aviana, Cult Neophyte |
| R6 `R_FREEZE` | Frozen пропускает следующую возможную атаку; время снятия зависит от того, атаковал ли персонаж в этом ходу | wiki «Freeze» | Frostwyrm's Fury |
| R7 `R_TURN_COUNT` | Отложенный старт считает начала ходов указанного игрока после создания эффекта; эффект включается в начале N-го такого хода | wiki «Aviana, Elune's Chosen» (notes) | Aviana |
| R8 `R_SCRIPTED_SPELL_DAMAGE` | У карт с `ImmuneToSpellpower` Spell Damage применяет процедура карты: у split — к числу ударов (как в `IR_SPEC.md`), у остальных — **UNKNOWN**, требует зависимости | HearthstoneJSON (тег), wiki «Spell Damage» | Torch |

**Контракты данных:**

* DA1. Токены по префиксу ID и статам остаются **SUPPORTED**; для CONFIRMED нужен источник связей (hsdata
  `CardDefs.xml` или Power.log) — отдельная задача и отдельное разрешение на загрузку.
* DA2. Для оружия в снимках 25xxxx прочность берётся из `health` (`durability = 0` у 248 из 251 коллекционного оружия).
* DA3. `pred:card_class` проверяет `classes`, если поле есть, иначе `cardClass`. Как мультикласс с искомым классом
  отвечает на отрицание — **UNKNOWN**, требует CONDITIONAL-зависимости.

### 3.2 Уровень 2 — структура

**S1. `op:FREEZE {to}`** + R6. Нужна Frostwyrm's Fury; 15 упоминаний в рамке; 4 декларации ManaEngine; уже была в
списке пробелов пилота A. Вариант «`ENCHANT keywords: [FREEZE]`» отклонён: Frozen — это **состояние** со своим
правилом снятия, а слово Freeze на карте-существе обычно означает «замораживает того, кого ранит». Смешивать опасно.

**S2. Параметр экземпляра (вторая волна, по отдельному дизайну).** Декларация объявляет `params`
(`{"dmg": {"n": 8, "mark": "$", "spell_damage": "CARD_PROCEDURE"}}`), значения читаются как `{"param": "dmg", "of": …}`,
меняются операцией `SET_PARAM {to, param, value}`, а параметр с `persist: true` переживает перемещение между зонами.
Нужен Torch («Return this to hand with any excess damage»); тот же механизм — естественное место для клиентских
плейсхолдеров `{0}/{1}` (36 карт рамки: Herald-придатки, улучшающиеся карты). Риск высокий: где живёт параметр, что
копируется при Copy/Transform, как он виден SELF и Policy. **Вводить только после отдельной дизайн-записки и не
меньше 3 карт выборки, которым он нужен.** Без S2 Torch честно остаётся PARTIAL.

## 4. Семантические контракты и инварианты валидатора

| Изменение | Инварианты валидатора | Двусмысленность / опасность |
|---|---|---|
| E1 `alive` | только в `cond:is` над `ref`/`SELF`; требует R3 в списке правил | спутать с `damaged` — разные предикаты; «if it dies» = `alive: false` |
| E2 `attacker` | у `ATTACK_DECLARED` поля `attacker`/`defender`; `subject` — ошибка; `HERO_ATTACK` эквивалентен `attacker = свой герой` и подлежит той же проверке | перенаправленная атака (Misdirection) — CONDITIONAL-зависимость, не тихое правило |
| E3 `NEXT_TURN` | только у `ADD_PLAYER_EFFECT`/`ENCHANT`; вместе с `player` эффекта | эффект, созданный на ходу затронутого игрока, относится к его **следующему** ходу; это фиксируется правилом, а не текстом карты |
| E4 `THIS_GAME` | не сочетается с `uses` без `UNTIL_USED`-семантики | — |
| E5 `starts_after` | `N ≥ 1`; число должно совпасть с числом текста, включая слова «two/three» (словарь числительных уже есть в `semantic_lint.py`) | чьи ходы считаются — всегда явно `player` |
| E6 | `applies_to` без `uses` и с `UNTIL_USED` — ошибка | старые декларации A с `uses: 1` не меняют смысл |
| E7 | `measure: AMOUNT` только у `DAMAGE_DEALT`; `source` обязателен, если текст сужает источник («with spells») | граничные источники («заклинание, сыгранное эффектом», Secret на своём ходу) — CONDITIONAL-зависимость |
| E8 `mul` | ровно два операнда, хотя бы один — литерал, совпадающий с числом текста | — |
| E9 `position` | `RANDOM` требует слова «shuffle», `TOP/BOTTOM` — «top/bottom» (обе стороны якоря) | предел размера колоды — UNKNOWN, CONDITIONAL |
| E10 | `CARD_PROCEDURE` без `ImmuneToSpellpower` в метаданных — ошибка; без split-шаблона требует UNKNOWN_RULE-зависимости (R8) | нельзя использовать, чтобы «убрать» `$` у обычной карты |
| S1 `FREEZE` | `to` — селектор персонажей; слово «freeze» в спане ↔ `FREEZE` (кроме выдачи ключевого слова существу) | порядок с уроном и призывом задаётся `seq`, не правилом |
| R1 | `ADD_TO_HAND` с `from_zone` в `PLAY` автоматически подключает R1 | ветка «рука полна» обязана быть описана в conformance-сценарии |

## 6. Проверки: что исправить и что требует независимого источника

### 6.1 Почему ошибки проходили

* Статус вычисляется только из наличия `unexpressed` и зависимостей. Проверки не сравнивают **смысл** спана с IR, кроме
  чисел, меток `$`/`#` и нескольких лексических якорей.
* `reminders` не проверяются по содержанию, не попадают в рендер и не понижают статус. Любое правило можно объявить
  напоминанием и получить FULL (3 из 9 диагностических ошибок).
* Лексические якоря покрывают глаголы операций, стороны, зоны и тайминги, но не условия («if/survives»), отрицание
  («non-»), окна времени («next turn»), позицию в колоде, субъект события.
* Рендер не показывает `condition` у триггеров, роли события атаки, `reminders`, а эффект игрока без `uses` показывает
  как «for the next card». Ревью «по рендеру» эти места не видит.
* Связь `unexpressed.why` ↔ конкретная зависимость не проверяется (это заметил и Codex: удаление одной CORE-зависимости
  не ловится, пока остаются другие причины PARTIAL).

### 6.2 Детерминированные проверки (можно сделать сразу)

| ID | Проверка | Что ловит из диагностики |
|---|---|---|
| C1 | `reminders` только для текста внутри `<i>…</i>` или скобок в исходном тексте либо из закрытого списка шаблонов напоминаний; напоминание с глаголом действия → ошибка; рендер показывает напоминания | Torch, Frostwyrm, Aviana (`reminders`) |
| C2 | Покрытие глаголов: каждый глагол действия спана (deal, destroy, draw, summon, freeze, return, put, shuffle, give, gain, restore, discover, transform, silence, cost…more/less, repeat, cast, get, add) сопоставлен узлу своей семьи в той же способности, иначе спан должен быть `unexpressed` | пропущенные шаги вообще |
| C3 | Условия: «if / survives / dies / while / unless» ↔ `if`/`condition`/`while`/`alive` | Nascent Bolt (безусловный добор) |
| C4 | Отрицание: «non-X / except / other» ↔ `exclude` (или будущий NOT) | V'ama («destroy all») |
| C5 | Окна времени в обе стороны: «next turn» ↔ `NEXT_TURN`; `THIS_TURN` требует «this turn»; `{turns}` — «N turns»; `THIS_GAME` — «this game» | Cult Neophyte (`THIS_TURN`) |
| C6 | Колода: «top/bottom of … deck» ↔ `position`; `RANDOM` (shuffle) требует «shuffle» | Imp (shuffle) |
| C7 | Субъект события: «your hero attacks» ↔ `HERO_ATTACK`; «this attacks» ↔ `attacker: SELF`; `HERO_ATTACK` требует «hero» | Magma Hound (`HERO_ATTACK`) |
| C8 | У каждого `unexpressed` и каждой CORE-зависимости явная ссылка друг на друга; UNRESOLVED-решение ссылается на зависимость того же спана | удалённая CORE-зависимость (пробел из README B1) |
| C9 | Инварианты метаданных: статы, расы и ключевые слова токена совпадают с описанием в тексте («8/8 Demons with Taunt and Lifesteal»); E10 только с `ImmuneToSpellpower`; прочность оружия из `health` | неверный токен, «снятие» `$` |
| C10 | Полнота рендера: каждый ключ декларации отображается (тест «нет невидимых полей») | скрытые условия и роли |
| C11 | Несколько `play`-способностей у заклинания → предупреждение «порядок между способностями не определён» | разрезанная последовательность Frostwyrm |
| C12 | Регрессионный набор: 9 диагностических ошибок + мутанты A/B; цель — все пойманы без новых предупреждений на исходных декларациях | — |

Оговорка: якоря C3–C7 написаны тем же автором, что и ошибки диагностики, и читают тот же английский. Пройденный набор
C12 — это проверка согласованности, а не оценка доли ложного принятия.

### 6.3 Что требует независимого семантического источника

* **Выбор правила игры:** чьи ходы считает лунный цикл, Spell Damage при `ImmuneToSpellpower`, excess при Divine Shield,
  мультикласс. Источник — правила с цитатой, затем Power.log (RULE-EVIDENCE), затем gold.
* **Идентичность токенов и семейств** (Deathwing) — данные связей, не текст.
* **Неявные соглашения текста** («a minion» — любая сторона; «your cards» — какие зоны) — частично детерминируемы, но
  сами соглашения нужно подтверждать.
* **Полнота и эквивалентность кодировки:** два автора могут написать разные, но равносильные IR. Предлагаемый дешёвый
  детектор — **два независимых авторства** (другая модель или другой промпт без доступа к первому) и нормализованный
  структурный diff. Расхождения идут на gold; на совпадениях gold делается выборочно, чтобы оценить ложное согласие.

## 8. Прогноз полноты для 12 карт

| Состояние | FULL | FULL_DEP | PARTIAL | FULL + FULL_DEP |
|---|---:|---:|---:|---:|
| B1 как есть | 1 | 0 | 11 | **1/12** |
| v0.1, лучшее авторство (композиция; проверено валидатором) | 1 | 2 | 9 | **3/12** |
| + уровень 0 (правила R1–R8, данные) | 2 | 2 | 8 | **4/12** |

(В строке уровня 1 FULL: Warblades, Waggle Pick, Nascent Bolt, Cult Neophyte; Neophyte может оказаться FULL_DEP.)
Останется PARTIAL: **Ultraxion** — формула `{1}`, зона скидки, выбор Soldier вне Herald-классов и список Deathwing
неизвестны; v0.2 это не решит и не должна притворяться, что решает.

Баланс по проблемам:
* **новых универсальных элементов** реально нужно: 1 структурная операция (FREEZE) для 10/12; ещё 1 структурный
  механизм (S2) для 11/12; 9 параметров/значений/ролей (E2–E10) + 1 необязательный предикат (E1);
* **только уточнением правил** решается: Waggle Pick целиком; split у Magma Hound; динамичность у Neophyte; момент
  проверки выживания у Nascent Bolt; порядок модификаторов стоимости — 5 проблем;
* **внешние данные** нужны 4 картам (Ultraxion; токены Spellweaver's, Imp, Frostwyrm) и ещё 2 картам — контракт
  прочности оружия;
* **v0.2 не решит:** Ultraxion; объём «your cards» у Aviana; Spell Damage, Divine Shield и полную руку у Torch;
  мультикласс у V'ama; перенаправленную атаку у Magma Hound — они остаются явными зависимостями. И главное — v0.2 не
  делает авторство надёжнее: чем больше выразимо, тем больше мест для правдоподобных ошибок (раздел 6).

## 9. Не слишком ли это дорого для 12 карт

* **Структура компактна.** С моим минимальным набором новый структурный элемент нужен 2/12 картам = **17 %** (Codex
  предлагал структуру для 6/12 = 50 %). Порог полной B — ≤25 % на последних 30; тренд благоприятный, но 12 карт мало.
* **Поверхность параметров не насыщена.** Хотя бы один новый элемент любого уровня нужен **7/12 = 58 %** карт (Aviana,
  Spellweaver's, Imp, Neophyte, Magma Hound, Torch, Frostwyrm). В последней трети A было 61 %, порог полной B — ≤45 %.
  Это честный сигнал: словарь растёт, хотя и элементами, которые являются базовыми примитивами Hearthstone, а не
  логикой карт.
* **Окупаемость по экрану.** Почти каждый элемент упоминается в рамке многократно: FREEZE 15, «after … attacks» 27,
  «next turn» 20, «(N) less for each» 17, `ImmuneToSpellpower` + `$` 11, плейсхолдеры 36. Исключение — счётчик суммы
  урона (2–4): его можно отложить, оставив Spellweaver's PARTIAL, если нужно сэкономить.
* **Где реальная цена.** Каждый элемент — запись словаря, ветка валидатора, строка рендера, якорь линтера и 2–4
  conformance-сценария. Это дёшево. Дорого другое: правила R1–R8 подтверждены пока только wiki, и проверка авторства
  (раздел 6). Ни то, ни другое не зависит от размера языка.

Вывод: v0.2 в объёме «уровень 0 + уровень 1 + FREEZE» не дорог относительно выгоды и не создаёт карточной логики.
S2 и HERALD — не сейчас.

## 10. Рекомендуемый порядок внедрения

1. **Gold по 12 картам B1** пользователем, с CARD_AUDIT как подсказкой; отдельно решить спорные места (Spell Damage у
   Torch, мультикласс, объём «your cards»).
2. **Ужесточение проверок до роста словаря:** C1 (reminders), C10 (полнота рендера), C3–C7 (якоря), C8 (связь пропусков
   с зависимостями), C9 (метаданные), C11; регрессионный набор C12. Старые модули оставить замороженными для
   сравнимости, новые — отдельными, как сделано с `semantic_lint.py`.
3. **Слой правил** R1–R7 с источниками; R8 — как явное UNKNOWN.
4. **`card-ir/0.2`**: E1–E10 и S1 как обратно совместимые дополнения; декларации v0.1 остаются валидными.
5. **Переавторство 12 карт B1** под v0.2 с промптом «сначала композиция»; сравнить с прогнозом раздела 8.
6. **Следующие 18 карт** — два независимых авторства + diff + gold на расхождениях; считать структурную и любую новизну.
7. **Только по данным:** S2, HERALD, `damage_result`, событие начала хода, NOT для условий.
