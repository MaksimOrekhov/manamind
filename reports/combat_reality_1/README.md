# COMBAT-REALITY-1 — арифметика атак на реальных матчах

**Решение: NO-GO для следующего fit и numeric residual.** Наблюдаемые числовые
отношения доступны для всех 740 легальных атак «существо → существо», но локально
проверенный обмен — только для 28 атак train и ни одной validation. Эти 28 альтернатив
принадлежат десяти решениям четырёх матчей. Это слишком мало для обучения на
достоверных последствиях. Исследование завершено без обучения и без загрузки моделей.

## Данные и проверяемая гипотеза

Гипотеза: нулевое покрытие NCA связано с требованием полностью vanilla-поля,
а не с отсутствием атак. Baseline — неизменённый `combat_features()` из
NUMERIC-COMBAT-ABLATION-1 со своей сохранённой metadata. Протокол записан до сканирования:
[PROTOCOL.md](PROTOCOL.md). Использованы прежние 32 train-матча и 7 validation-матчей
из `real_policy_retrain_1/retrain_manifest.json`, с проверкой состава решений.
Реальный test, синтетические контроли и модели не открывались.

Новый offline extractor находится в `src/manamind/training/combat_reality.py`.
Production Policy, StateEncoder, LIVE, overlay и `manamind.outcome` не изменены.
Ветка продолжает commit `6eee3ba0d01f63af98ece9890ec9552a5a286a56`:
TL1 → TL2 → NUMERIC-COMBAT → COMBAT-REALITY; merge/rebase не выполнялись.

## Почему NCA возвращал нули

Его gate требует **для каждого существа на обоих полях** известную metadata,
тип MINION, пустой текст и пустой список механик. Дополнительно запрещены
Reborn/Lifesteal/Windfury/Dormant, secrets/quests, Locations, active effects и
evidence constraints. Флаги должны быть явно известны ещё до десериализации.

Все 740 атак существ имеют хотя бы одну блокировку непосредственно у источника
или цели; 699 дополнительно блокируются другими существами. Поэтому убрать только
проверку чужого текста недостаточно. При этом Battlecry, уже отработавший при выходе,
не равен неизвестной реакции на текущую атаку: blanket vanilla-гейт чрезмерно строг.

| Причина baseline, на атаках существо → существо | Train, из 651 | Validation, из 89 |
|---|---:|---:|
| Текст непосредственного источника/цели непустой | 624 | 86 |
| Их mechanics непусты | 624 | 86 |
| Их metadata отсутствует | 261 | 17 |
| Непустой текст другого существа | 600 | 84 |
| Metadata другого существа отсутствует | 364 | 39 |
| Прямой Lifesteal flag | 123 | 23 |
| Прямой Reborn flag | 81 | 5 |
| SELF secret/quest objects | 332 | 75 |
| Opponent secrets | 141 | 54 |
| SELF Locations | 284 | 46 |
| Opponent Locations | 66 | 14 |
| Неизвестные проверяемые minion flags | 0 | 0 |
| Active effects / evidence constraints | 0 / 0 | 0 / 0 |

Причины пересекаются; их нельзя складывать. Наличие Location или Deathrattle не
доказывает, что именно оно изменит эту атаку. Это объяснение старого отказа.
`secret_count` у SELF включает quest objects; его нельзя трактовать как число
неизвестных вражеских секретов. Отсутствие записанных active effects не доказывает,
что экспорт содержит все постоянные эффекты и enchantments игры.

## Контракт локальных свойств

Каждое значение содержит `value`, `knownness`, `reasons`, `conditions`.

| Уровень | Значение и граница утверждения |
|---|---|
| OBSERVED | `Attack ≥ target Health`, их разность, `source Health − target Attack`, величина target Attack. Только отношения текущих чисел; не обещание уничтожения или выживания. |
| CONDITIONAL | Урон двух обычных пакетов, снятие щитов, гибель исходных тел, Health после пакета. Действительно только если атака дошла до тех же тел, stats/flags не изменились и неизвестные реакции не вмешались. |
| VERIFIED_LOCAL | Тот же локальный пакет без видимой блокировки в ограниченном контракте Outcome. Не гарантия полного игрового состояния или полноты всех механик Hearthstone. |
| UNKNOWN / отсутствие свойства | Нужных чисел/флагов/пакета нет, source/target не совпадают с действием либо действие вне области. Причина возвращается явно; None не становится False. |

Числовые отношения считаются из current stats, отдельно от base metadata.
Урон, снятие щитов и гибель читаются из событий существующего `forecast_action()`;
новых правил разрешения боя нет. Health после пакета — арифметический остаток до
healing/Reborn/Deathrattle, может быть отрицательным; **это не Health готового GameState**.
При Poisonous тело может погибнуть при положительном остатке. Поэтому «выжил»
означает отрицание `body_dies` в заявленном локальном обмене, а не `Health > 0`.

Прототип не обращается к `_candidate`, `exact_state()` или `partial_state()`.
Статус полного Outcome сохраняется: 35 EXACT / 616 PARTIAL в train, 89 PARTIAL
в validation. Из 28 локально проверенных атак 12 имеют EXACT и **16 PARTIAL**:
у них остаются только открытые последствия SELF quest, не меняющие перечисленный
пакет. Таким образом, полный EXACT не является обязательным требованием.
Windfury unknown об оставшихся атаках ограничен bookkeeping `can_attack`;
прототип не обещает число оставшихся атак.

Любой `alters_listed` unknown, кроме этого bookkeeping, сохраняет условность.
Добавлены более строгие ограничения на непроверенную область аур, active effects,
evidence constraints и пассивный текст оружия. Это не ослабляет глобальный Outcome.
Произвольная аура может предотвращать/заменять урон, даже если current buff уже
отражён в цифрах. Для оружия существующий forecaster проверяет атакующее оружие
героя; прототип дополнительно отказывается от уверенного minion exchange при
непроверенном пассивном оружии на любой стороне.

Использованы текущий pinned Standard catalog и **существующий**
`data/outcome/reviewed_texts.json`, включая уже проверенные token texts и printed
Reborn stats. Каталог модели и vocabulary не менялись. Разведочный прогон только
с урезанной NCA metadata давал 11 локально проверенных атак; полноценный существующий
text source поднял число до 28. В той урезанной metadata отсутствовали printed stats,
что искусственно добавляло `REBORN_BASE_UNKNOWN`. Промежуточные результаты сохранены
локально; заключение использует окончательный прототип и исходные данные.

Это консервативные, пересекающиеся препятствия. Например, неизвестное Lifesteal

удалить такую неизвестность из доказательства. BOARD_STATIC_TEXT включает
неразобранные ограничения и тексты Locations, а не только боевые защитные эффекты.
BOARD_TEXT_MISSING часто относится к token, а не к атакующему.

В реальных парах встречались Divine Shield (19 train-атак), Poisonous (5 validation),
Reborn (81/5), непосредственно участвующие Deathrattle cards (168/12), AURA (88/10),
Locations (322/48), оружие (98/32), opponent secrets (141/54).
Immune у двух участвующих тел и неизвестные проверяемые minion flags не встретились;
они проверены отдельными отказами/арифметическими тестами, а не объявлены проверенными
реальными примерами. Неизвестные hero flags не используются в этом прототипе.

## Проверка последствий и ручной аудит

Из 165 фактически выбранных атак 68 были «существо → существо». Для 57 из них есть
следующее решение с **соседним числовым decision number в том же SELF turn**.
У 52 есть хотя бы один сопоставимый endpoint. Повторяющиеся card IDs и Reborn
не используются для угадывания тождества. Отсутствие тела — proxy для его гибели;
Health и Shield следующего решения — endpoints, не прямое наблюдение отдельного
damage packet. После действия могли разрешиться триггеры, замены и воскрешения.

| Проверки endpoints | Train | Validation |
|---|---:|---:|
| CONDITIONAL согласуется | 111 | 19 |
| CONDITIONAL расходится | 2 | 0 |
| VERIFIED_LOCAL согласуется | 10 | 0 |
| VERIFIED_LOCAL расходится | 0 | 0 |

Десять проверок локально подтверждают слишком малую выборку; они не независимы и
не доказывают игровой силы. 130 согласий условных расчётов не превращают оставшиеся
реакции в известные. Урон пакета напрямую этими endpoints не подтверждён.

Два расхождения относятся к **одной** выбранной атаке: 3/6 атакует 1/4, но в следующем
решении атакующего нет, а цель остаётся на 4 Health вместо условно рассчитанного 1.
Число opponent secrets уменьшилось с 1 до 0. Extractor заранее вернул CONDITIONAL
с OPPONENT_SECRET, BOARD_TRIGGER, BOARD_STATIC_TEXT и BOARD_TEXT_MISSING.
Это правильный отказ от гарантии; конкретную причину перенаправления/удаления по
этим двум snapshots мы не устанавливаем.

Отдельно вручную просмотрены девять первых примеров по заранее определённым
pre-action признакам, без Policy scores. Ожидаемые числа записаны независимо в
`scripts/report_combat_reality.py`: 108 проверок значений и 108 проверок уровней
прошли. [manual_audit.json](manual_audit.json) содержит анонимные локальные свойства.

| Пример | Ручная проверка и правильная граница |
|---|---|
| 1: 3/2 → 1/4, Location/static context | Обычный остаток 1/1; статический контекст оставляет CONDITIONAL. |
| 2–3: 3/6 → 6/6, Deathrattle card / оружие | Источник достигает 0, цель 3. Цель не погибает в обычном обмене, поэтому её Deathrattle не утверждается сработавшим; неизвестные token/static/weapon effects сохраняют отказ. |
| 4: 2/5 → 3/2 Lifesteal, секрет | Источник 2, исходная цель погибает; healing/conversion/секрет неизвестны. |
| 5: 2/5 → 2/1 Reborn token | Гибель исходной цели не означает отсутствие существа после Reborn; returned stats неизвестны. |
| 6: 3/1 → 2/3 | Оба исходных тела погибают в локальном обмене; локальный контракт проходит. |
| 7: 4/5 → 2/2, aura и Deathrattle | Обычный источник 3, цель погибает; неизвестные реакции/аура не позволяют гарантировать endpoints. |
| 8: 1/2 → 4/4 Divine Shield | Цель теряет щит, Health остаётся 4; источник погибает. Неизвестный другой token блокирует гарантию. |
| 9: 2/1 Poisonous/Reborn → 3/3 | Обычный урон 2 оставляет цели 1 Health, но Poisonous убивает исходное тело; у источника отдельный Reborn. |

Изолированные тесты также проверяют Immune, щиты обеих сторон, вражеский Poisonous,
неизвестные boolean, damage prevention, triggers, ауры, оружие, секреты,
неизменность входа и независимость от chosen label/future/hidden fields.

## Что делать с механической информацией дальше

1. **Для отношений текущих чисел данных достаточно; для гарантированных исходов нет.**
   740 атак приходятся на 257 решений; reliable subset — 28 альтернатив в десяти
   train-решениях и ноль validation. Расширять fit на таком subset преждевременно.
2. В обычной игре доступны current Attack/Health, арифметические margins и явно
   наблюдаемые minion flags. Щит/Poisonous можно использовать как наблюдаемые свойства;
   их взаимодействие с пакетом остаётся условным при неизвестных реакциях.
3. Production encoder уже содержит текущие числа и mechanics. В будущей отдельно
   разрешённой работе можно сохранить encoder и использовать offline auxiliary
   relations или отдельный experimental adapter с новым checkpoint schema и masks.
   `CONDITIONAL` нельзя склеивать с known=true для реального уничтожения. В этой задаче
   не создан ни adapter для Policy, ни checkpoint, ни auxiliary fit.
4. **Отдельный numeric residual сейчас не оправдан.** Предыдущая абляция дала выигрыш
   только на части synthetic unknown-ID вариантов; здесь нет достаточной независимой
   real validation для надёжных combat targets. Изменение точки подключения чисел
   не исправляет неизвестные эффекты или недостаток независимых состояний.
5. Сохранять тактические тесты как проверку controlled arithmetic разумно; очередное
   синтетическое обучение не отвечает на найденный real blocker. Предпочтительное
   следующее исследование без fit: точнее связать существующие visible observed-facts
   и тексты с областью воздействия на отдельный пакет, обеспечить provenance minion
   flags и привязку endpoints к attack-resolution событиям. Изучать прежде всего
   missing token texts, постоянные/временные эффекты и secret/reaction boundary;
   не снимать unknown только ради процента покрытия и не строить второй движок.
   Лишь после появления достаточного validation-покрытия и новых независимых
   тактических состояний имеет смысл отдельно обсуждать ограниченный ML-пилот.

NO-GO относится к новому обучению на гарантированных kill/survive или numeric residual.
Наблюдаемые арифметические отношения и явные условные признаки полезны для offline
анализа уже сейчас; их влияние на качество Policy в этом исследовании не измерялось.

## Воспроизводимость и техническая проверка

```powershell
.venv\Scripts\python.exe scripts/combat_reality_audit.py --out data/processed_combat_reality_1/final
.venv\Scripts\python.exe scripts/report_combat_reality.py
```

Оба runner требуют новых выходных файлов и не перезаписывают результаты. Для повторного
анализа укажите новый локальный путь; report runner по умолчанию использует сохранённый
`final` и отказывается перезаписывать опубликованные агрегаты. Параметры `--local` и
`--out` позволяют проверить новый локальный прогон в отдельной папке. Ввод сохраняется byte-for-byte,
hashes до/после совпали. Частные поэлементные записи и samples остаются в ignored
`data/processed_combat_reality_1/`. Raw logs, snapshots, game_id/decision_id, модели
и player names в публичные артефакты не включены.

Ruff `src scripts tests` прошёл. 105 профильных тестов прошли; полный pytest без
четырёх optimizer/training-тестов: **1000 passed, 1 skipped, 4 deselected, 1 failed**.
Единственное падение — существующий migration guard, обнаруживший старую untracked
папку `vendor/RosettaStone` в рабочем каталоге. Она не используется, не добавляется
в Git и сохранена как посторонняя работа. Никакие исключения не вносились в тест.
Pinned catalog offline воспроизведён (два файла), Git diff каталога пуст.
Детали: [verification.json](verification.json). Новых обученных checkpoints нет;
существующие тесты сериализации используют только свои временные fixture-файлы.
