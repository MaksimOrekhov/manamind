Дата: 2026-10-15. Ветка `codex/ml-prepare-train-1` от `main` `f5efca5`. Без merge. LIVE Policy, `--prepare-actions`
по умолчанию, ManaEngine, Outcome Shadow, Collector, Overlay, старый корпус и старые checkpoint не менялись.
`fresh_holdout` **не открывался** (файлы 9 его матчей не читались ни для обучения, ни для inference; только имена файлов

**Что измеряется.** Везде ниже — совпадение с действием игрока (Behavior Cloning): cross-entropy (CE), Top-1, Top-3
(только меню ≥ 3 действий), MRR. Это не оптимальность хода и не сила игры; доказательств игровой силы здесь нет.

## 1. Гипотеза, baseline, правила вердикта (записаны до запуска)

Файл `configs/ml_prepare_train_1/experiment.json`, коммит `67e42fd` (до первых полноразмерных прогонов).

- **Гипотеза.** Добавление 442 решений с Prepare в меню (action schema 2, 49 реальных выборов `PREPARE_CARD`) улучшает
  имитацию игрока на решениях с Prepare и не снижает её на остальных.
- **Baseline.** Контроль: та же архитектура, seed, конфигурация, те же матчи, но только решения action schema 1 (то, что
  могли использовать все прежние checkpoint). Нижняя граница — равновероятный выбор.
- **Правила** (95 % интервалы — bootstrap по целым матчам, 2 000 повторов, seed 20261015, пары «Prepare − контроль»,
  усреднение по seed, пул validation + test_seen = 26 матчей):
  - P1: разность CE на меню с Prepare < 0 и верхняя граница интервала < 0;
  - P2: она < 0 отдельно в validation и test_seen и не менее чем в 2 из 3 seed в каждой части;
  - N1: на меню без Prepare среднее ≤ +0.03 и верхняя граница ≤ +0.05;
  - N2: Top-1 = Prepare на меню с Prepare не чаще чем в 2× от доли выбора Prepare игроком;
  - PROMISING — всё P1, P2, N1, N2 для архитектуры, общий — для обеих; REGRESSION — среднее ухудшение ≥ +0.05 на меню
    без Prepare в обеих частях либо Top-1 Prepare > 3× доли игрока; иначе INCONCLUSIVE.

## 2. Что изменено в коде

Выбран минимальный вариант: тот же обучающий цикл `scripts/train_policy_v3.py`, без дублирования.

- `train_policy_v3.run(..., allow_prepare=False, prepared=None)` — по умолчанию поведение и метаданные прежние
  (тест: у контроля нет ключа `allow_prepare`, его checkpoint — обычный schema 1 и загружается без флага; запуски без `allow_prepare` на строках schema 2 по-прежнему отказывают до обучения). `prepared=(parts, split)`
  подаёт готовые разбиения вместо `frozen_split.json`.
- `policy_checkpoint`: `save_policy_checkpoint(..., allow_prepare=True)` пишет `semantic_action_schema_version = 2` и
  `experiment.allow_prepare = True`; `load_policy_checkpoint(..., allow_prepare=False)` **по умолчанию отвергает**
  такой checkpoint (то есть он не загрузится в LIVE, shadow и прежние скрипты). Подмена версии в обе стороны отвергается
  (в том числе «тихое понижение» Prepare-checkpoint до schema 1). Prepare-checkpoint допустим только для v2/v3.
  В `split` допускается `reserved_game_ids` (матчи, исключённые из всего); их пересечение с любой частью — ошибка.
- `policy_metrics.evaluate(..., allow_prepare=False)`.
- Размерность входов **не менялась**: используется существующий признак `prepare_card` (колонка в `ACTION_FEATURE_NAMES`).
- `scripts/ml_prepare_train.py` — обучение групп по `split_plan.json`; `scripts/ml_prepare_analyze.py` — только inference
  и таблицы. Тесты: `tests/test_ml_prepare_train.py` (11), `tests/test_ml_prepare_analyze.py` (8).

## 4. Прогоны

Конфигурация одна, из ML-POLICY-V3-1 (hidden 64, dropout 0.1, AdamW lr 1e-3, wd 1e-3, batch 32, clip 1.0, ≤ 60 эпох,
patience 8, min_delta 1e-4, CPU, 1 поток); обучение с нуля; гиперпараметры не подбирались. Seed 42 → проверка корректности
→ 43, 44. Всего 12 прогонов (2 архитектуры × 2 группы × 3 seed), каталог `data/processed_policy_prepare_train_1/` (в Git не
входит). Лучшая эпоха (seed 42/43/44): prepare_v2 10/10/9, control_v2 10/14/10, prepare_v3 7/5/4, control_v3 3/5/4.
Время 54–266 с на прогон (до 10 процессов параллельно).

**Воспроизводимость.** Пилотный прогон seed 42 на более раннем коммите (`superseded_pilot_code_67e42fd/`, сохранён) и
финальный дали **побитово одинаковые веса** во всех 4 группах. Сохранение → загрузка → совпадение весов и логитов
проверяется внутри каждого прогона и тестами.

## 7. Сравнение с прежними checkpoint

Те же меню и состояния (validation + test_seen), без пересмотра весов. **У всех прежних checkpoint признак `prepare_card`
никогда не обучался**, поэтому на меню с Prepare это сравнение «никогда не видел» против «видел». Это не независимая оценка,
а описательное сравнение: матчи test_seen уже использовались в прежних экспериментах; у `policy_v3_ml_policy_v3_1` 23 матча

## 10. Ограничения (что не доказано)

1. **Контроль не равен «тем же данным без Prepare-признака».** Он не видел ни 442 добавленных состояний, ни действия
   Prepare. Выигрыш на меню с Prepare смешивает «новое действие» и «больше таких состояний». Чтобы отделить, нужна абляция
   (те же 442 строки с обнулённым/удалённым `prepare_card` или без Prepare-выборов).
2. **Смещение выборки.** 442 добавленных решения — именно те, что прежний импортёр пропускал как `AMBIGUOUS_SELECTION`;
   «Prepare в меню» в корпусе совпадает с «раньше пропускалось».
3. **Малое число положительных примеров:** 33 выбора Prepare в обучении, 8 в validation, 6 в test_seen; `JAIL_913` — 12
   из 14. Выбор между розыгрышем и Prepare одной картой отдельно не оценивался.
4. **Validation использовалась для выбора эпохи, test_seen не независим**, `fresh_holdout` (9 матчей, 2 выбора Prepare)
   по плану не годится как независимая проверка (`INSUFFICIENT_FRESH_MATCHES`, `INSUFFICIENT_FRESH_PREPARE_CHOICES`).
5. Игрок мог ориентироваться на подсказки в LIVE; «имитация» — это не оптимальность.
6. Три seed — это оценка разброса, а не его гарантия; интервалы учитывают зависимость решений в матче, но не
   неопределённость обучения.
7. Fine-tuning прежних checkpoint не исследовался.

## 11. Рекомендации для следующего этапа

1. Не включать Prepare-checkpoint в LIVE/shadow. Если shadow понадобится, сначала явно разрешить загрузку
   (`allow_prepare`) в shadow-слое; отдельной задачей.
2. Абляция для вывода 1: обучить v2 на тех же матчах и строках, но с `prepare_card = 0` у Prepare-действий; сравнить с
   `prepare_v2` на меню с Prepare. Малые прогоны, 3 seed.
3. Копить новые матчи с Prepare в меню (особенно не `JAIL_913`) и оценивать на них один раз после фиксации моделей;
   нужно хотя бы 10 новых матчей и ~20 выборов Prepare, как требует план split.
4. Если пойдём дальше, ориентироваться на v2: на этих данных он проходит все условия, а v3 слегка проседает на
   `HERO_POWER`/`END_TURN`; различие архитектур на смешанных данных не доказано.
