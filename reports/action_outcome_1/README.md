**Выбранное решение — небольшой чистый Python-модуль над видимым состоянием**, а не движок:

```text
GameState (видимое)  +  действие из меню  +  тексты карт (закреплённый каталог, затем reviewed-добавка)
        │
        ▼
 грамматика текста ──► Clause (DAMAGE / HEAL / BUFF / GRANT / DESTROY / ARMOR / COND / OPAQUE ...)
        │
        ▼
 World: рабочая копия + примитивы (урон, лечение, статы, ключевые слова, смерть) в порядке разрешения
        │
        ├─► Change[]  (цель, поле, до → после, причина; после=None + граница, если значение не определено)
        ├─► Event[]   (упорядоченные шаги: «щит поглотил 5», «условие ложно — предложение пропущено»)
        ├─► Unknown[] (что неизвестно и может ли оно менять посчитанное)
        └─► after_state (GameState только с точными изменениями)  ─►  Status: EXACT / PARTIAL / UNSUPPORTED
```

Почему так: цель — проверяемый результат, а не симулятор. Ручная реализация карт уже оказалась слишком дорогой;
текстовая грамматика даёт универсальный принцип (один шаблон покрывает все карты с таким текстом) и сразу
сообщает, где текст вышел за её рамки. Второй игровой движок не создаётся: нет очереди триггеров, выбора случайных
исходов и ответов противника.

## 2. Что возвращает механизм

`forecast_action(state, action, texts, context) -> Forecast`; `forecast_alternatives(...)` вызывает его для каждого
действия отдельно из одного и того же состояния. Область — разрешение самого действия «до момента, когда SELF снова
может действовать»; ход противника и последующие решения не моделируются.

| Что нужно различать | Как выражено |
|---|---|
| Точные непосредственные изменения | `Change` с `after` (например, `attack: 6 → 11 (+5)`) |
| Частично определённые | `Change` с `after=None` и границей: `health: 20 → ? (at least 28)` — лечение / урон, зависящие от ненаблюдаемого значения |
| Неизвестные эффекты или взаимодействия | `Unknown(kind, detail, alters_listed, adds_unlisted, tag)` — «может ли менять посчитанное» и «может ли добавлять непосчитанное» |
| Не поддерживается | `Status.UNSUPPORTED` + `unsupported_reason`, `after_state=None`; число не придумывается |

`Status.EXACT` означает: все прямые изменения вычислены из наблюдённых значений и **ни одного** неизвестного нет.
Любое неизвестное даёт `PARTIAL`. Неизвестные классифицированы тегами (`OPPONENT_SECRET`, `OWN_SECRET_OR_QUEST`,
`BOARD_TRIGGER`, `BOARD_STATIC_TEXT`, `DEATHRATTLE_OR_REBORN`, `BOARD_TEXT_MISSING`, `OWN_TEXT_UNPARSED`,
`OWN_TEXT_RANDOM`, `HEALING_BONUS_UNOBSERVED`, `SANCTUM_UNOBSERVED`, `SPELL_DAMAGE_UNOBSERVED`,
`HERO_SHIELD_UNOBSERVED`, `HAND_KEYWORDS_UNOBSERVED` и др.), чтобы считать, что мешает точности.
`Forecast.own_effect_known` — подтип: собственный текст действия понят и все нужные ему модификаторы наблюдены;
открыты только реакции других объектов.

Отсутствие информации не считается отсутствием эффекта: карта на столе без текста в каталоге, Secret противника,
триггер «после того как вы разыграете заклинание», Deathrattle/Reborn умирающего существа попадают в `Unknown`, а не
игнорируются.

## 3. Реально поддержанные механики

**Действия.** `PLAY_CARD` (заклинание, существо, локация), `HERO_POWER`, `ACTIVATE_LOCATION`, `ATTACK` (существо и герой,
в том числе с оружием), `END_TURN`. **Не поддержано** (`UNSUPPORTED`): розыгрыш оружия, обмен / ковка, выбор из
вариантов, действие не из меню SELF, позиция, где стоимость действия превышает показанную ману.

**Шаблоны текста** (предложение разбирается только целиком: лишнее слово делает его `OPAQUE`):
`Deal $N damage [to <селектор>]`, `Restore #N Health [to <селектор>]`, `Give <селектор> +A/+H [and <ключевые слова>]`
(а также `+A Attack`, `+H Health`, только ключевые слова), `Destroy <селектор> [with N or more/less Attack]`,
`Destroy the highest Attack enemy minion`, `Gain N Armor`, `Give your hero +N Attack this turn`,
`Gain N Mana Crystal(s) this turn only`, `If it dies/survives, <предложение выше>`, ключевые слова `Lifesteal` /
`Taunt` /… на заклинании, `Battlecry:` с такими предложениями, строки стоимости `Costs (N) ...`. Селекторы: `a minion`,
`an enemy minion`, `a character`, `all (enemy|friendly) minions|characters`, `your hero`, `the enemy hero`. Весь
закреплённый каталог (1185 карт) разбирается без ошибок; **полностью** понятный эффект сегодня у 35 заклинаний,
10 существ и 1 локации, ещё 77 заклинаний понятны частично — это осознанно малый и надёжный набор, а не покрытие
ради процента.

**Примитивы разрешения.**

| Примитив | Правило |
|---|---|
| Урон | Divine Shield поглощает пакет без потери здоровья; Immune — 0; броня героя поглощает первой; избыточный урон не теряется для Lifesteal; Spell Damage только у заклинаний и только к числам с `$`; карты с `ImmuneToSpellpower` бонуса не получают; урон силы героя / боевого клича / локации Spell Damage не получает; если Spell Damage не наблюдается — остаток здоровья и броня становятся границами «не более», а гибель при нижней оценке урона и поглощение щитом остаются точными |
| Лечение | `min(база + бонус лечения, недостающее здоровье)` на каждый пакет; без `healing_bonus` или `hero_max_health` — нижняя граница, не число; активный «лечение = урон» — `UNSUPPORTED` |
| Lifesteal | Лечит владельца на нанесённый урон **после всего** урона (важно для массовых эффектов); Divine Shield и Immune урон не наносят — лечения нет |
| Бафф | `+A/+H` поднимает текущее и максимальное здоровье вместе; повторная выдача уже имеющегося ключевого слова ничего не меняет |
| Уничтожение | Условие по текущей атаке обеих сторон; Immune-цель — `UNSUPPORTED` (правило не проверено); ничья по «наибольшей атаке» — случайность, неизвестное |
| Условие «если умрёт» | Вычисляется по предсказанному исходу: ложное условие снимает предложение целиком; «умрёт» при нижней оценке урона остаётся точным; «оно» без единственной выбранной цели — `UNSUPPORTED` |
| Бой | Урон одновременный; герой в защите не отвечает; Poisonous убивает только при реально нанесённом уроне; Stealth снимается; Windfury — оставшиеся атаки неизвестны; оружие теряет прочность, его Lifesteal / Poisonous берутся из наблюдённых механик, поломка оружия — неизвестное |
| Розыгрыш | Стоимость, уход карты из руки, вставка на позицию и перенумерация общего стола; тело существа из карты руки (ключевые слова — базовые, неизвестное `HAND_KEYWORDS_UNOBSERVED`); локация входит с прочностью, текст не выполняется |

**Реакции, которые считаются неизвестными** (ни одна не моделируется): Secret противника (по `secret_count`);
свои Secret / Quest; триггеры на столе по тексту («After you cast a spell», «At the end of your turn» — каждое с
классом события; непонятное условие считается «любым событием»); статические правила и текст локаций на столе;
Deathrattle и Reborn умирающих; карты на столе без текста; Enrage; оружие героя-атакующего.

**Ловушка данных.** В реальном корпусе `spell_damage` равен 0 во всех 4020 состояниях — импортёр его не заполняет,
это значение по умолчанию, а не знание (ENGINE-STATE-IMPORT-0 отметил то же). `healing_bonus = None` везде,
`hero_divine_shield = None` в 97% состояний. Поэтому по умолчанию урон заклинаний с `$` даёт неизвестное
`SPELL_DAMAGE_UNOBSERVED` и границы, а не число, лечение — `HEALING_BONUS_UNOBSERVED`. Вызывающий код может явно
поручиться за значение (`ObservedContext`), и тогда это записывается как допущение.

## 4. Универсальный принцип положительных эффектов и случай Hold Them Off!

Эффект «дать существу +A/+H и ключевые слова» не знает, чьё это существо. Механизм применяет изменение к цели и
записывает **владельца** цели (`Ref.side`). Сводка (`compare.summarise`) объективно считает, какая сторона получила
улучшение: если все точные изменения улучшают только объекты противника и не вредят ему, она так и пишет и называет
единственное прямое изменение SELF — потраченные ресурсы. Слова «ошибка» нет: такое действие может быть оправдано
комбинацией, которую прямые изменения не видят.

Воспроизводимый пример (`python scripts/action_outcome_demo.py`, [demo_hold_them_off.txt](demo_hold_them_off.txt)):

```text
[1] PLAY_CARD JAIL_913 -> OPPONENT minion #1 DEMO_ENEMY_6_6  ->  EXACT
      SELF player.available_mana: 5 -> 0 (-5)
      OPPONENT board#1 DEMO_ENEMY_6_6.attack: 6 -> 11 (+5)
      OPPONENT board#1 DEMO_ENEMY_6_6.health: 6 -> 11 (+5)
      OPPONENT board#1 DEMO_ENEMY_6_6.max_health: 6 -> 11 (+5)
      OPPONENT board#1 DEMO_ENEMY_6_6.lifesteal: False -> True
      net SELF: mana -5      net OPPONENT: board_attack +5, board_health +5, keywords +1
      note: direct effects only improve OPPONENT-controlled entities; SELF's direct change is the cost paid
            (strategic value, e.g. combos, is not assessed)
```

- **Какое существо выбрано** — по стороне, позиции общего стола и `card_id` из действия; одинаковые `card_id`
  различаются позицией (тест).
- **Универсальность.** `test_same_text_on_an_unrelated_card_id_gives_the_same_changes` подставляет тот же текст
  под другим идентификатором: изменения те же. `test_no_card_id_is_hard_coded...` сканирует исходники на зашитые
  идентификаторы. Текст `JAIL_913` берётся из закреплённого каталога (тест фиксирует разбор).
- **Prepare** в этом тексте считается ключевым словом «когда карту можно разыграть», а не «что делает розыгрыш».
  Это допущение записывается в каждый прогноз (`assumptions`). Проверка по логам: 20 реальных розыгрышей `JAIL_913`,
  во всех 20 цель получила ровно +5/+5 (Lifesteal новый в 18, в 2 уже был); других изменений самой цели в 19 из 20
  случаев нет, в одном `can_attack` цели изменился с False на True (причина по логу не установлена). **Все 20 были на
  своё существо** — врагу игрок баф не выдавал ни разу, поэтому «чужую» сторону проверяют контролируемые тесты и
  прогноз реального меню (раздел 5); арифметика от стороны цели не зависит.
- **Контрпримеры.** Цель уже с Lifesteal — меняется только +5/+5; цель с Divine Shield и Poisonous-боец — щит ломается,
  отравления нет; см. [demo_sequencing.txt](demo_sequencing.txt) и раздел 5.

## 8. Ограничения и неизвестные взаимодействия

- Это не полное состояние после хода: `after_state` — рабочая нижняя оценка; при `PARTIAL` поля с неопределённым
  значением остаются прежними и перечислены в `Change(after=None)`; при невозможном состоянии (стол больше 7) after-state
  не строится.
- Не моделируется ничего вне разрешения действия: ответ противника, начало хода, добор, случайность, Discover. Реакции
  других объектов только обнаруживаются.
- Сторона цели не оценивается по смыслу. «Только противнику» — констатация прямых изменений.
- Допущение Prepare подкреплено логами только для своих целей. Классификация «продолжение Battlecry / триггера или новая
  статическая строка» опирается на начальное слово предложения; необычный статический текст, начинающийся с глагола
  эффекта, был бы принят за продолжение.
- Сильные пробелы наблюдения (раздел 6): `spell_damage`, `healing_bonus`, `hero_divine_shield`, состояние Sanctum, Quest
  SELF, ключевые слова в руке, тексты токенов. Это ограничения экспорта, а не механизма.
- Грамматика покрывает малую часть текстов. Чаще всего в реальных ходах не понят `Imbue your Hero Power` (88), условное
  «return this to your hand» (60), `Give all enemy minions -N Attack until your next turn` (40), `Draw N cards` (33),
  `Deal $N damage randomly split` (33), Discover (32), Summon Cannoneers (27).
- Корпус — Priest (37), Warrior (13), Death Knight (3), ранговый Standard одного игрока.
- Время — локальный Python; нагрузка на UI-поток LIVE не измерялась.

## 10. Подготовка к оценке позиции (ValueNetwork)

Результаты зонда: [value_probe.json](value_probe.json); `scripts/action_outcome_value_probe.py` читает checkpoint'ы и ничего не
обучает.

1. **Можно ли построить корректный частичный after-state?** Да, как тип: `Forecast.after_state` — обычный `GameState`;
   1981 из 1981 реальных after-state проходят `StateEncoder` без ошибок. Но корректен как *позиция* он только при
   `EXACT`. При `PARTIAL` это нижняя оценка: непосчитанные реакции не применены, у 405 прогнозов есть поля с
   неопределённым значением, которые остаются старыми. Подавать такой state как истину нельзя — у энкодера нет маски
   «неизвестно» на уровне сущностей.
2. **Какие данные нужны.** (а) Совместимый checkpoint: ни один из 5 сохранённых value-checkpoint'ов не грузится в текущую
   схему энкодера (формат 1; схемы 2 и 3 против 16). (б) Наблюдение: `healing_bonus`, `healing_does_damage`, Quest SELF,
   Spell Damage, ключевые слова карт в руке, щит героя, тексты токенов. (в) Позиции «в середине хода» среди обучающих
   (покрытие не проверялось). (г) Остаток маны и рука после хода — модель должна уметь взвешивать их ценность.
3. **Ограничения текущей ValueNetwork.** Нет совместимой обученной версии; архитектура — DeepSets по зонам без выхода
   неопределённости; цель — результат партии, а не разность между соседними позициями; чувствительность к единичному
   изменению (например +5/+5) на малых реальных данных не проверена.
4. **Как сравнивать полные и частичные прогнозы.** Не одной скалярной оценкой. Предлагается: (i) `EXACT` / `own_effect_known`
   сравнивать по after-state; (ii) для `PARTIAL` оценивать интервал (нижняя оценка и варианты завершения по списку
   неизвестных: «сработает / не сработает» для каждого `alters_listed`) и выбирать действие только при доминировании
   интервалов; (iii) `UNSUPPORTED` оставлять на prior Policy. Альтернативная архитектура: вместо оценки after-state
   обучать `Q(состояние, действие, признаки прогноза)`, где признаки — вектор прямых изменений по сторонам (Δ сила стола,
   Δ здоровье героя, Δ мана, Δ ключевые слова, **плюс маска неизвестных по тегам**). Плюсы: устойчива к частичному
   покрытию, не требует полного состояния, строится на уже имеющихся 23 365 парах «меню + прогноз». Минусы: нужны новые
   размеченные данные и проверка на независимых матчах; закрывает класс ошибок Hold Them Off! (Policy видит прямые
   изменения), но не стратегию.
5. **Поиск нескольких ходов без полного симулятора.** `forecast_action` принимает любой `GameState`, поэтому цепочку из двух
   или трёх действий одного хода можно строить как макро-действие: применить прогноз первого действия, проверить, что
   второе из текущего меню всё ещё допустимо (источник и цель существуют, хватает маны, атака не потрачена), и прогнозировать
   его на after-state. Недостающая деталь — перенумерация `hand_index` и позиций стола после первого действия: `World` её
   знает, но наружу не отдаёт. Поиск ограничен цепочками, где все звенья `own_effect_known`; реакции остаются границей.
   Это самостоятельная задача.
