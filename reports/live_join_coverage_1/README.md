# LIVE-JOIN-COVERAGE-1 — безопасная дедупликация LIVE-снимков

Дата: 2026-10-18. Это техническая проверка сопоставления данных, не новый ML-тест. Протокол, исходные данные и опубликованные результаты NEW-MATCHES-EVAL-1 не менялись. Модели не оценивались и не запускались для inference.

## Итог

У 157 решений из 14 новых raw-матчей в записи LIVE встречались повторные снимки с одним ключом `(match_id, options_id, state_hash)`. Старый evaluator отклонял любой такой ключ до проверки рекомендаций и shadow-журналов. Проверка на совпадение всех полей snapshot кроме `seq`, уникальность `seq`, пересчёт `state_hash`, уникальность raw-решения и существующие проверки журналов разрешила безопасно добавить **63 решения**.

Из оставшихся 94 повторных решений **92 исключены из-за конфликтующих Outcome Shadow строк**: различается поле `actions`, поэтому повторные прогнозы нельзя считать одной записью. Ещё для **2 решений нет строки Frozen v2 recommendation**. Эти строки не объединялись. Новая техническая выборка содержит **302 решения в тех же 13 матчах**. Число матчей не выросло: один из 14 raw-кандидатов вообще не имеет LIVE-снимков.

## Проверенная процедура

[`scripts/live_join_coverage_1.py`](../../scripts/live_join_coverage_1.py) выполняет только read-only join-диагностику на 14 непересекающихся keyed raw-срезах из предыдущего протокола, их `snapshots.jsonl` и строках соответствующих shadow-журналов. Защищённые `fresh_holdout` ID исключались до разбора JSON-строк общих shadow-журналов. Их содержимое и LIVE-снимки не открывались. Общие старые Power.log и 18 legacy-файлов не читались. Скрипт проверяет историю сплитов в закреплённых метаданных checkpoint, но не загружает модели для вычислений.

Повтор считается одним событием только если:

1. Все snapshot-строки — `MAIN_ACTION` и имеют один `(game_key, options_id, state_hash)`.
2. `state_hash` совпадает с пересчитанным хешем полного состояния.
3. Все сериализованные поля кроме `seq` совпадают побайтно в canonical JSON; `seq` — положительные целые без повторов.
4. На raw-ключ приходится ровно одно решение.
5. Рекомендация, Strategy Shadow и Outcome Shadow существуют, не конфликтуют и относятся к `seq` из проверенной группы. Checkpoint рекомендации совпадает с закреплённым Frozen v2; действия Top-3 присутствуют в raw legal menu.
6. Strategy и Outcome Shadow проходят исходную строгую проверку полного **упорядоченного** меню: размер, все индексы без пропусков и точное совпадение каждого действия на своей позиции.

Последний пункт реализуется прежней функцией `_match_menu_actions`; порядок или полнота меню не ослаблялись. В 92 конфликтных случаях проверка завершалась раньше из-за разных Outcome Shadow `actions`, поэтому эти решения не считаются проверенными по меню и остаются исключёнными.

## Распределение 513 импортированных решений

| Технический результат | Решений | Матчей |
|---|---:|---:|
| Ранее опубликованный точный join, подтверждён контрольной диагностикой | 239 | 13 |
| Безопасно восстановленный join среди повторных снимков | 63 | уже входили в эти 13 матчей |
| Повторный снимок, конфликтующие Outcome Shadow `actions` | 92 | — |
| Повторный снимок без Frozen v2 recommendation | 2 | — |
| Нет связанного LIVE-снимка | 103 | — |
| Уникальный LIVE-снимок есть, но нет Frozen v2 recommendation | 14 | — |
| **Доступно после проверки** | **302** | **13** |

Проверка совпала с закреплённым baseline: 239 прежних exact joins. После разрешения повторов сумма по исходным 513 решениям замыкается: 302 доступных, 92 конфликта Outcome, 16 решений без recommendation (14 уникальных плюс 2 повторных) и 103 без LIVE-снимка.

Для 103 решений не нашлось ни snapshot с тем же `options_id`, ни snapshot с тем же `state_hash`. Как отмечено в [`COLLECTOR-COVERAGE-AUDIT-1`](../collector_coverage_audit_1/README.md), 51 из них принадлежит матчу без LIVE-снимков вообще, остальные 52 распределены между матчами с LIVE-покрытием, но относятся к отсутствующим состояниям/меню. По имеющимся файлам безопасно восстановить эти решения нельзя.

Подробные локальные агрегаты с псевдонимами матчей сохранены в игнорируемом `data/processed_live_join_coverage_1/diagnostic.private.json`. Содержимое матчей и shadow-прогнозы в отчёт не копировались.

## Collector и неразрешённые источники

В [`scripts/run_manamind.py`](../../scripts/run_manamind.py) добавлен `--collector-max-sessions N`. Допустимы только положительные целые; значение по умолчанию остаётся **3** и передаётся существующему Collector. Фильтр допустимых Ranked Standard матчей и остальные правила сбора не изменены.

Предыдущий аудит обнаружил шесть локальных папок Hearthstone-сессий: при текущем окне Collector три старейшие папки не сканируются. Он не хранит историю путей, поэтому само наличие папок вне окна не доказывает, что игры из них пропущены. В этой задаче расширенный сбор не запускался. 18 legacy-файлов не имеют ключа матча в имени; их содержимое и общие старые Power.log не читались, так как без предварительной проверки там могут оказаться защищённые игры.

* Среди 14 уже разрешённых raw-кандидатов 13 матчей имеют exact join до изменений; дедупликация добавляет решения, но не матчи. Четырнадцатый кандидат без LIVE-снимков из имеющихся raw-файлов не восстанавливается.
* Возможные дополнительные матчи в старых папках/legacy-файлах пока неизвестны. Для их обнаружения сначала нужно отдельное разрешение на локальную read-only проверку старых источников с исключением holdout по ID. Массовый импорт не нужен и не выполнялся.
* Перед следующей игровой сессией достаточно держать Collector запущенным; новая сессия обычно входит в окно последних трёх папок. Параметр `--collector-max-sessions 6` предназначен для явно разрешённого catch-up-сканирования. Его не запускали на текущих старых папках.
* До безопасного восстановления дополнительных матчей остаётся **12 новых пригодных матчей** до порога 25: после дедупликации число матчей остаётся 13. Если отдельная read-only проверка найдёт ещё полные матчи с корректным LIVE-join, нужное число можно будет пересмотреть в новом протоколе.

## Проверки и неизменённые области

Добавлены тесты для схлопывания снимков, конфликтов состояния/решения/метаданных, повторного `seq`, строгого порядка меню, значения Collector по умолчанию, передачи явного лимита и отказа на нулевом лимите. Не менялись NEW-MATCHES-EVAL-1, LIVE Policy, Model Shadow, Prepare, raw-логи, датасеты и checkpoint. Не выполнялись обучение, сравнение моделей или массовое сканирование логов.
