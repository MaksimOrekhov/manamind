существующие датасеты не менялись. Policy v2, LIVE-рекомендации, Outcome Shadow и Strategic Scorer не трогались.

**Итог:** восстановлены все **12** ранее отклонённых матчей — **570** размеченных решений. Шлюз недостоверного
состояния отклонил **3** решения. Строгий аудитор датасета: privacy **PASS**, split **READY**. Пересечений с
существующими датасетами 0, дубликатов 0.

## Почему возникал `GAME_RESET`

Это не перезапуск игры, а механика **Rewind** дополнения Time Travel: карта или сила героя перематывает случайный
результат. Сервер откатывает стол: `BLOCK_START BlockType=GAME_RESET` → `RESET_GAME` → `FULL_ENTITY - Updating …`
для сущностей.

- В 12 сырых матчах 14 событий. Источники: Blessing of the Bronze (`END_000p`, 5), `TIME_034` (4), `TIME_433` (2),
  `TIME_004`, `TIME_018`, `TIME_EVENT_999` (по 1).
- В логе каждое событие видно дважды: строка `GameState` и её повтор `PowerTaskList`.
- Сбросы происходили в середине и конце партий (ходы 7–42). В 8 случаях из 11 проверенных их делал соперник в свой
  ход.

## Что сброс действительно делает недостоверным

`hslog` применяет сброс так:
- сначала у **каждой** карты стирается личность (`card_id`, `revealed`); остальные теги остаются;
- затем у каждой переотправленной сущности теги **заменяются целиком** (`FULL_ENTITY - Updating`).

Сущность, которую блок **не** переотправил, остаётся со старыми тегами и без `card_id`. В реальных логах таких
2–5 на сброс в зонах PLAY и HAND: экипированное оружие, служебное зачарование перемотки, карты без типа. Если
построить видимое состояние, пока такая сущность лежит в руке, на столе, в колоде или секретах, оно может
ошибаться: оружие без личности, неверный размер руки или колоды. Поэтому снимать защиту глобально нельзя.

## Исправление (минимальное)

`src/manamind/integrations/powerlog/game_reset.py` плюс 10 строк в `policy_import.py`. Глобальный отказ от матча
заменён проверкой **каждого** решения после последнего сброса:
- решение принимается, только если каждая сущность в зонах HAND, PLAY, DECK, SECRET (обеих сторон) после сброса
  была переотправлена `FULL_ENTITY`;
- засчитывается только `FULL_ENTITY`, потому что он заменяет все теги. `SHOW_ENTITY` и `CHANGE_ENTITY`
  дописывают теги поверх старых и не засчитываются. На этих данных строгий и мягкий варианты дают одинаковый
  результат;
- если хоть одна сущность устарела, решение пропускается с причиной `GAME_RESET_STALE_STATE`. Ничего не
  достраивается, а ошибка самой проверки тоже означает «не доверять».

Решения до первого сброса и матчи без сброса обрабатываются ровно как раньше.

Что ещё изменено:
- новая причина внесена в явный список допустимых причин пропуска (`training/real_policy.py`). Схема манифеста
  матча **не** изменена;
- в reducer добавлен только read-only доступ к уже применённым пакетам (`applied_packets`), LIVE-поведение не
  меняется.

Все прежние шлюзы сохранены: Ranked/Standard, завершённость, SELF, результат, мультивыбор
(`AMBIGUOUS_SELECTION`), `OPTIONS_SUPERSEDED`, приватность, канонический round-trip.

## Гарантии корректности

- Строгий `audit_real_policy_dataset.py`: privacy PASS, split READY, манифесты согласованы с решениями и исходами.
- Дубликаты: 570/570 уникальных `decision_id`, повторов `state_hash` внутри матча 0, пересечений с прежними
  датасетами 0. Backfill отказывается писать в существующий каталог; повторный импорт того же матча штатно даёт
  `DUPLICATE_MATCH`.
- Чужой игрок: класс SELF и класс соперника постоянны во всех решениях каждого матча. SELF и результат
  определяются тем же кодом по `PLAYSTATE` в конце матча, перемотка их не меняет.
- Результат: проверен по описанию матча пользователем — Demon Hunter против Rogue, победа, 21 ход (`91c21889`):
  `final_result = 1.0`, 21 ход. Прямое сопоставление с Value-примерами невозможно: у Value-файлов случайный
  `game_id`.
- Тесты (`tests/test_policy_game_reset.py`):
  - матч со сбросом больше не отклоняется;
  - после полного сброса решение принимается и читает **перемотанные** значения;
  - непереотправленное существо соперника блокирует следующее решение;
  - непереотправленная скрытая карта в руке соперника тоже блокирует;
  - без сброса ничего не меняется;
  - отклонённые строки проходят строгий аудит.
- Повреждённый (обрезанный) блок сброса закрывается как `PARSE_ERROR`, строки не пишутся.

Ограничения: проверить состояние после перемотки по «внешней истине» нельзя — лог её не содержит, а в 8 из 11
сбросов перемотку делал соперник в свой ход. Гарантия строится на правилах применения пакетов: сущность после
сброса учитывается, только если её полное описание пришло заново. Механические наблюдения
(`manamind.evidence`) по-прежнему пропускают такие матчи; это вне задачи.

## Как выполнить backfill после принятия

1. Сформировать восстановленные данные отдельно и проверить:

   ```bash
   python scripts/backfill_game_reset_policy.py data/raw/collected --output data/processed_game_reset_recovery_1/policy --existing data/processed_policy_real/collected data/processed_data_checkpoint_1_20261010/canonical data/processed_policy_ml2a/seed42_v2/dataset
   python scripts/audit_real_policy_dataset.py data/processed_game_reset_recovery_1/policy
   ```

2. После решения о включении: штатный backfill дописывает в рабочую коллекцию только отсутствующие матчи. Уже
   существующие дают `DUPLICATE`; Value и наблюдения идемпотентны.

   ```bash
   python scripts/process_completed_match.py data/raw/collected
   ```

Новые партии после merge обрабатываются коллектором автоматически по новому правилу.
