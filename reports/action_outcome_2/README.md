# ACTION-OUTCOME-2 — теневое прогнозирование последствий в LIVE

11 октября 2026. Ветка `claude/action-outcome-2` от `origin/main` `a5e0c98` (OBSERVATION-EXT-1a уже в `main`). Обучения нет, merge не выполнялся.
Ранжирование Policy v2, Top-3, оверлей, `StateEncoder`, `GameState`, `state_hash`, checkpoint'ы, датасеты и ManaEngine не менялись; новые матчи не
собирались; ValueNetwork не подключался; поиска комбинаций нет; поддержка карт не расширялась. Все числа ниже — диагностика на **уже просмотренных**
32 LIVE-записях (6–11 октября), а не независимый контроль качества игры или рекомендаций.

## Итог

1. **Теневой режим подключён минимально и выключен по умолчанию.** `python scripts/run_manamind.py --outcome-shadow` прогнозирует последствия **каждого**
   легального действия показанного решения тем же `manamind.outcome` и пишет их в отдельный `prediction_journal.outcome_shadow.jsonl`. Второй LIVE-системы нет:
   используются тот же `Snapshot` (с `Snapshot.observed` → `ObservedContext`) и то же меню, которое уже проверила Policy (`Recommendation.menu` — всё меню
   в порядке ранга Policy; Top-3 — его первые три элемента, как раньше).
2. **Нулевое влияние на Policy — проверено на 32 записях.** Реальный `UnifiedRuntime` прогнан по каждой записи трижды (без тени, с тенью, с тенью повторно): выводимый
   текст, события для оверлея (включая ранги и оценки), хеши состояний, строки `RECOMMENDATION`/`INVALIDATION` — **совпадают на всех 2002 решениях**. Отдельно
   ранжирования на неизменённом `main` и на ветке совпадают побитово (sha256 по всем рангам и оценкам, все 32 записи, `policy_vs_main.json`).
3. **Прогнозы воспроизводятся.** Повторный прогон даёт идентичные строки (без времени). Независимо от этого анализатор заново пересчитал прогнозы по
   `slice.log` (через офлайн-импортёр, а не через LIVE-путь): совпали **20 554 из 20 554 дайджестов** прогнозов, контекст наблюдённых фактов — 1634 из 1634,
   меню — 1634 из 1634.
4. **`PARTIAL` не превращается в `EXACT`.** Инварианты проверены на всех 24 706 записанных действиях (нарушений 0); из выбранных игроком действий, у которых есть
   наблюдение результата, `EXACT` было 17 — **все 17 подтверждены, 0 противоречий**; `EXACT` у не-`END_TURN` действий всего 133 из 22 704 (0,6 %).
5. **Заметная часть `PARTIAL`-прогнозов содержит подтверждённый прямой эффект.** Из 22 242 `PARTIAL`-действий (без `END_TURN`) у 14 747 (66 %) есть хотя бы одно точное изменение,
   у 11 913 (54 %) собственный эффект действия понят целиком (`OWN_EFFECT_KNOWN`). Против наблюдения: **1314 подтверждённых / 9 опровергнутых** утверждений-эффектов на
   `OWN_EFFECT_KNOWN` (99,3 %) и **4342 / 55** на `PARTIAL_LOCAL` (98,7 %). Это точность локальных прямых эффектов, а не оценка хода (раздел 6).
6. **Задержка приемлема, показ рекомендации не замедлен.** Тень считается *после* показа и записи рекомендации: медиана 2,4 мс на решение, p95 11 мс, максимум 100 мс
   (4 действия из 24 706 дольше 20 мс; причина не установлена). Полный шаг решения: медиана 5,7 → 9,5 мс, p95 9,5 → 21,4 мс (интервал опроса 50 мс). Бюджет 250 мс на решение ни разу
   не исчерпан (`NOT_COMPUTED` = 0).
7. **Тесты:** полный набор **871 passed, 1 skipped** (было 802), `ruff` чист; 69 новых тестов; 43 из 43 мутаций финального кода убиты (раздел 9).
8. **Что полезного нашлось про выбор действия, а не про покрытие:** действия, прямые эффекты которых улучшают только противника («подарки»), игрок не выбрал **ни разу из 1634**
   решений, хотя меню содержит такое действие в 519; Policy поставила подарок на первое место в 14 решениях (0,9 %). Но выигрыш от ручного фильтра мал (+2 в Top-1, +6 в Top-3
   из 1634), поэтому следующий эксперимент предлагается другой (раздел 11).

## 2. Как запускать

```bash
# LIVE: обычная работа + тень (журнал рядом с prediction_journal.jsonl)
python scripts/run_manamind.py --ui --outcome-shadow
# разбор накопленных партий (повторяемо; незавершённые партии отмечаются как «не привязаны», а не угадываются)
python scripts/outcome_shadow_report.py --shadow data/raw/live/prediction_journal.outcome_shadow*.jsonl \
    --recordings-root data/raw/live --out reports/<новая папка>/shadow_report.json
# проверка «нулевого влияния» на записях
python scripts/outcome_shadow_replay.py <каталоги записей> --data-root <data> --out-dir <новая папка> --report-json <новый файл>
```

Код возврата отчёта `0`, если все «ворота» чистые (`invariant_violations`, `unreadable_lines`, `forecast_digest_mismatches`, `exact_forecasts_contradicted` = 0), иначе `1`;
отчёт при этом записывается. Существующий файл отчёта не перезаписывается. Анализ новых партий «по мере появления» — это повторный запуск той же команды: 2002 решений
(32 партии) разбираются за ≈ 40 с.

Воспроизведение этого отчёта (данные — в основном checkout `E:\ManaMind\data`, в git их нет):

```bash
ls -d E:/ManaMind/data/raw/live/Hearthstone_*/*/ > recordings.txt
python scripts/outcome_shadow_replay.py $(cat recordings.txt) --data-root E:/ManaMind/data \

```

## 3. Журнал

Строки (`docs/LIVE_BRIDGE.md`, раздел Outcome shadow): `OUTCOME_SHADOW` (одна на показанное решение), `OUTCOME_SHADOW_ERROR` (теневой расчёт не получился: стабильный код),
`OUTCOME_SHADOW_INVALIDATION` (решение перестало быть текущим — прогноз становится историей; причина та же, что у `INVALIDATION`).

* Связь: `match_id` (= `game_key`), `seq`, `options_id`, `state_hash`, `decision_id` (то же значение, что у `RECOMMENDATION`).
* На действие: индекс меню, **ранг Policy**, метка (ID карты, позиции), хеш действия, `status` (`EXACT/PARTIAL/UNSUPPORTED` или `NOT_COMPUTED/ERROR`), `tier`, точные эффекты, границы,
  теги неизвестного (`KIND:tag`, без свободного текста), дайджест полного прогноза, микросекунды.
* Не хранится: сырые строки Power.log, имена, скрытые карты, копия состояния (оно в записи; дайджесты позволяют доказать, что анализатор пересчитал тот же прогноз), текст карт.
  Тест с «канареечными» скрытыми картами и именами подтверждает отсутствие в журнале.
* Размер: ≈ 7 КБ на решение (14 МБ на 2002 решения, ≈ 440 КБ на партию). Ограничено: ≤ 24 эффекта на действие (дайджест всё равно покрывает все), ≤ 160 действий в меню,
  файл ≤ 64 МиБ (затем переименование с UTC-меткой и новый файл).
* Выключено → файл тени не создаётся и формат прежних строк тот же; включено → прежние строки не меняются (тест сравнивает их побайтно без временных меток).
* Ошибка/неуспевание: `OUTCOME_SHADOW_ERROR` с кодом (`NO_MENU`, `STATE_UNREADABLE`, `FORECAST_FAILED`, `SHADOW_RUNTIME_ERROR`), ошибка одного действия → `ERROR` только у него,
  исчерпанный бюджет → `NOT_COMPUTED` у оставшихся (прогноз не выдумывается); сбой записи в журнал → предупреждение `outcome shadow warning: <тип>` и счётчик; в конце сессии печатается строка
  `outcome shadow: N/M decisions recorded, … ms median, … p95, … max`.

`HEALING_DOUBLING_UNVERIFIED` (362), `HEALING_BONUS_UNOBSERVED` (116).

`NO_TARGET_FOR_CHOSEN_CLAUSE` 2.

## 7. Проверка по фактическим действиям

Анализатор разделяет (выбранное действие определено по логу **после** партии и не участвует в построении прогноза):

* **Выполненное действие** (1634 решения привязаны к завершённым партиям; 1117 из них имеют наблюдение результата, у 517 его нет: `END_TURN`, последнее действие хода — `NO_OBSERVATION_AFTER_ACTION`).
* **Альтернативы**: 18 920 действий, фактического результата в логе нет → только подсчёт, не оценка.
* **Утверждения**: 8751 подтверждено, 183 опровергнуто (2,0 %). Опровергнутые, по причине: объявленное самим прогнозом неизвестное (`DECLARED_GAP`) 158, пробел наблюдения (`OBSERVATION_GAP`) 14,
  согласуется, но не доказано (`CONSISTENT_UNCONFIRMED`) 6, ограничение сравнения одинаковых ID 3, подтверждённая реакция 1, **не объяснено 1**. «Объяснено» здесь означает, что причина названа или
  совместима, но не что она подтверждена.
* **Пропущенные изменения** (наблюдение изменило то, чего прогноз не заявлял): 972; объявленные неизвестные 812, согласуются, но не подтверждены 72, подтверждённые реакции 23, пробелы наблюдения 38, **не объяснено 27**.
* **Необъяснённые** (28 записей в 10 решениях, полный список в `shadow_report.json`): превращение карт руки семейства `TLC_817t*` после розыгрыша `JAIL_913`/`CORE_EX1_197` (14), появление существа на столе при розыгрыше
  `CORE_SW_068` (3), потеря существа и добор после атаки `TLC_600` (6), урон героям и потеря Divine Shield при атаках `TLC_817t5`/`FIR_777` (3), `can_attack` после `JAIL_913` (1), здоровье после атаки `EDR_494` (1). Это
  кандидаты для следующей порции правил/наблюдений, не оценка ошибок.
* **`EXACT`-прогнозов, опровергнутых наблюдением: 0.**
* **Согласие с игроком**: выбор игрока был Top-1 Policy в 794 из 1634 решений (48,6 %), в Top-3 — в 1132 (69,3 %). Это имитация игрока на просмотренных записях и не доказательство оптимальности ни хода игрока, ни рекомендации.

## 11. Следующий ограниченный эксперимент: CONSEQUENCE-RERANK-0 (предложение, не запущен)

**Почему не «фильтр подарков».** Измерено на этих же данных (`opponent_only_improvement` в отчёте): подарок в Top-3 стоял в 88 из 1634 решений, но вынув подарки, выбор игрока попал бы в Top-1 дополнительно
в 2 решениях и в Top-3 в 6 (+0,12 п.п. и +0,37 п.п.); лучшая из оставшихся рангом альтернатива совпала с выбором игрока в 2 из 14 случаев, «та же карта с иной целью» — в 1 из 8. Ручное правило безопасно, но мало
что даёт: подтверждённые эффекты надо использовать в выученном виде.

**Гипотеза.** Небольшая модель, получающая для каждого из Top-K кандидатов Policy v2 (K = 5) её логит, ранг и признаки прогноза (статус/ярус, чистые изменения метрик сторон по *точным* изменениям с маской «неизвестно»,
флаг «подарок», затраты маны, тип действия), точнее предсказывает действие игрока, чем логит Policy один.

**Базовые линии на тех же данных:** Policy v2 один (Top-1 48,6 %, Top-3 69,3 % на этих 1634 решениях, просмотренных); Policy + ручной фильтр подарков; случайный порядок внутри Top-5.

**Данные и разбиение.** Каноническая реальная выборка + новые естественно сыгранные партии с включённой тенью; разбиение по `game_id`; для логита Policy брать только партии, на которых Policy v2 не обучалась
(иначе её логит оптимистичен). Прогнозы пересчитываются офлайн из состояния и фактов решения (тот же код, что в LIVE; дайджесты это проверяют).

**Модель и ограничения.** Условный логит (softmax по 5 кандидатам), ≤ 25 весов, L2, CPU, секунды; пять seed; без изменения Policy, `StateEncoder`, checkpoint'ов, ValueNetwork, без поиска.
Требует отдельного разрешения с записанными лимитами (политика проекта: обучение не стартует само).

**Ворота (до запуска).** Успех: прирост Top-1 ≥ +2,0 п.п. с 95 % интервалом (парный бутстреп по партиям) выше 0 на ≥ 30 независимых матчах (≈ 1900 решений; при доле несовпадений ≈ 8 % — допущение — стандартная ошибка ≈ 0,7 п.п.);
ни одно семейство (`PLAY_CARD`, `ATTACK`, `HERO_POWER`, `END_TURN`) не теряет > 1 п.п.; признаки используют только точные изменения. Провал: прирост < +1 п.п. или интервал включает 0 → остановка, прогнозы остаются журналом.
Имитация игрока, технические проверки и качество игры — отдельные утверждения; успех здесь доказывал бы лишь лучшее воспроизведение выбора игрока, а выигрыш в играх — отдельной проверкой на независимых партиях.
