# MODEL-FIRST-3A — Card Representation Pilot

**Статус: INCONCLUSIVE.** Исходная Policy v2 заметно меняет ранжирование при замене ID embeddings на общий UNK, но данные не позволяют утверждать, что это улучшает качество на новых картах. Проверка на реальных решениях использует уже просмотренную test-часть; новые четыре матча из usage registry отсутствуют в предоставленном снимке корпуса. Text и Hybrid не обучались и не оценивались как игровые политики.

Эксперимент основан на `codex/model-first-2c` (`cfcc8197433a3c7fdb4bb92ff1077e09d2986fe6`) и существующем принятом checkpoint Policy v2 от ML-2A. Checkpoint, production `CardFeatures`, `StateEncoder` schema 16, Policy v2 и загрузчик не менялись. Ни одного обучения не запускалось.

## Результаты

### Замороженная Policy v2 на ранее использованном test split

В checkpoint test-разбиении два матча дают 60 решений. Эта группа уже использовалась для предыдущей оценки checkpoint, поэтому ниже — только повторное описание, не независимый новый holdout. В каждом из 60 решений есть по меньшей мере один ID, отсутствовавший в train-наблюдениях checkpoint. 27 из 50 различных видимых ID отсутствовали в train; 28 ID нашлись в pinned catalog, у 27 из этих 28 есть rules text.

| Вариант входа той же замороженной Policy v2 | Top-1 | Top-3 | MRR | N |
|---|---:|---:|---:|---:|
| ID embeddings сохранены | 27/60 (45,0%) | 44/60 (73,3%) | 0,6158 | 60 |
| Все ненулевые entity/action card IDs заменены на UNK; прочие тензоры неизменны | 21/60 (35,0%) | 38/60 (63,3%) | 0,5172 | 60 |

ID-preserving вариант выше на 6/60 Top-1 на этой уже просмотренной группе. Все 60 решений имеют хотя бы один ID, отсутствующий в train, поэтому здесь невозможно показать сравнимый seen-ID сегмент. При этом модель не переобучалась на отдельный «Structural» вариант; это **абляция ID входа**, а не честное сравнение отдельно обученных ID и Structural policy.

Покрытие выбранных действий в группе: `PLAY_CARD` 31, `END_TURN` 17, `HERO_POWER` 7, `ATTACK` 4, `ACTIVATE_LOCATION` 1. Показатели по каждому типу приведены в `results.json`. Top-1 ID-preserving модели по двум матчам — 43,9% и 47,4%; двух кластеров недостаточно для надёжной оценки неопределённости.

### Контроль MODEL-FIRST-2C для влияния ID

На 20 подготовленных ID-counterfactual парах (40 строк) проверен точный контроль входных данных: менялись только entity ID и action card ID тензоры; state features, структурные entity features, action descriptors и links побитово совпадали. Между обычными и UNK входами сменился top action в 20/40 строках; максимум абсолютного изменения логита — 1,496. Top-1 checkpoint на локальных gold сценариях — 0/40 с обеими версиями входа. Следовательно, ID embeddings влияют на выбор, но эта проверка не демонстрирует улучшение рекомендаций.

На одном решении исторического Policy v2 test split максимальная абсолютная разница логита равна 1,562, а top action меняется. Тот же тест тензоров подтверждён на каждой строке 2C ID-группы. Синтетические 2C сценарии ранее просмотрены и не являются оценкой реальной силы.

### Текстовый адаптер и доступность данных

Добавлен локальный воспроизводимый TF-IDF adapter (слова и биграммы) на закреплённом `standard_current_enUS.json`. Используется только поле `text` с правилами, HTML-разметка очищается; flavor text не читается. Пустой/неизвестный текст даёт пустой вектор с `present=false`. В adapter-выводе отдельно остаются ID, тип, базовые cost/attack/health и mechanics; текущие характеристики передаются отдельным полем и не заменяют базовые. Sparse cache зависит от SHA каталога и hash конфигурации.

Учет корпуса: 32 матча / 1 227 решений, все пять типов выбранных действий представлены. Registry сообщает четыре `NOT_KNOWN_USED`, но ни один из них не присутствует в этом корпусе. Актуальный fresh split proposal — 0 матчей и 0 решений (`NO_CLEAN_THREE_WAY_SPLIT`). Поэтому Text/Hybrid обучение не запускалось, а использованный ранее test split не был повторно объявлен новым holdout.

| Представление | Результат MODEL-FIRST-3A |
|---|---|
| ID | Frozen Policy v2; историческая test-абляция выше |
| Structural | Та же Policy v2 с ID→UNK; не отдельная обученная модель |
| Text | Не оценивалось как Policy; измерено только наличие rules text и извлекаемость sparse TF-IDF признаков |
| Hybrid | Не оценивалось: нет сопоставимого обучающего и независимого test-разбиения |

TF-IDF строится по локальному pinned каталогу, а не по размеченным матчам. 4 476 терминов получены из 1 185 записей каталога. Это проверка извлечения текстовых признаков, но не свидетельство их полезности для выбора игрового действия. Прямого диагностического gold набора семантических свойств в рамках этого пилота не создавалось.

## Ответы на вопросы

1. **Насколько Policy зависит от индивидуальных ID?** Зависимость измерима: в синтетических контрфактических парах top action поменялся в 20/40 строк; на историческом test split результат также изменился при ID→UNK. Однако в 2C Top-1 был 0/40 в обеих версиях, так что полезность этого влияния не доказана.
2. **Помогают ли структурные признаки на unseen cards?** Изолированная абляция не показывает улучшения: ID→UNK снизил Top-1 с 45% до 35% на двух ранее использованных тестовых матчах. Это не новое независимое подтверждение и не сравнение двух обученных representation.
3. **Есть ли измеренная польза текста?** Установлено покрытие правилами и создан воспроизводимый TF-IDF вектор. Влияние на ranking не измерялось, поэтому пользы для игровых рекомендаций пока не показано.
4. **Достаточно ли данных для Text/Hybrid обучения?** Нет. Нет ни одного пригодного clean three-way split; четыре неиспользованных registry матча не входят в текущий corpus snapshot.
5. **Следующий оправданный эксперимент?** Сначала получить/допустить новый матчевый корпус с заранее зафиксированными train/validation и независимым unseen-card test, после чего отдельно оценить небольшой Text/Hybrid adapter. Этот пилот сам по себе не оправдывает переход к обучению новых представлений.

## Воспроизведение

Команда запускалась в PowerShell из корня ветки; пути к локальному corpus/checkpoint не добавляются в Git:

```powershell
$env:PYTHONPATH = 'src'
python scripts/model_first_3a.py `
  --dataset E:\ManaMind\data\processed_policy_real\refresh_obs1_final `
  --registry E:\ManaMind\data\processed_policy_real\refresh_obs1_final\experiment_usage_registry.json `
  --checkpoint E:\ManaMind\data\processed_policy_ml2a\seed42_v2\policy.pt `
  --counterfactual E:\ManaMind\model-first-2\data\processed_synthetic\model_first_2c\test.jsonl `
  --output reports\model_first_3a\results.json `
  --cache-dir E:\ManaMind\.tmp\model_first_3a
python -m ruff check src tests scripts
python -m pytest -q
```

`results.json` фиксирует hashes checkpoint, каталога и корпуса, точные знаменатели, разрезы по action type и ID train-presence. Результаты зависят от локальных игнорируемых данных; они намеренно не добавлены в репозиторий. Проверки Linux/Windows выполняются workflow после push.
