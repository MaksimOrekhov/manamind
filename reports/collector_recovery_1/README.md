# COLLECTOR-RECOVERY-1

Дата проверки: 2026-10-26. Ветка: `codex/collector-recovery-1`, база `f4a5b9202f5486f54230aed2344ecda82917e715`.

## Вывод

Коллектор смешивал сохранение raw с результатом Value: `FAILED` от Value превращал весь матч в `PARSE_FAILED`, хотя raw уже был записан и Policy/Evidence могли завершиться. Следующий 5-секундный poll заново записывал тот же raw-срез и повторял все этапы. Причина `SELF_AMBIGUOUS` была отдельной проблемой идентификации стороны.

По локальным незащищённым логам выявлена неверная предпосылка в LIVE/Policy: код собирал все `player` из `SendChoices.m_chosenEntities` в один набор и трактовал набор более чем с одним владельцем как локальный конфликт. В шести из восьми Policy-отказов в этом поле присутствовали два владельца. Ещё в одном матче mulligan-сигнал конфликтовал с однозначной стороной, выведенной из видимой руки; в последнем случае локальная сторона осталась неразрешённой. Power.log содержит эти данные, но они не доказывают, какой из двух владельцев является клиентом. Поэтому автоматический выбор стороны не добавлялся.

Value импортёр использует только число известных карт в руке: на одном из 36 проверенных raw матчей этот сигнал не разрешил SELF. Это отдельное fail-closed ограничение. Остальные результаты не подтверждают общий сбой формата Power.log, парсера или сегментатора: Value был обработан для 34 матчей, а Policy создал данные для 28.

## Что проверено и защищено

- В `data/raw/collected` найдено 175 raw-срезов. До чтения логов 139 были исключены по match ID из split/evaluation lock-файлов и использованных матчей. Для 36 оставшихся выполнена постобработка в одноразовых временных каталогах; каталоги удалены после подсчёта.
- В этих 36 диагностических обработках Value: 34 `OK`, один `SELF_UNRESOLVED`, один `PROCESSOR_RUNTIME_ERROR`. Policy: 28 `OK`, 8 `SKIPPED` по SELF-неопределённости/конфликту. Это число матчей, а не число строк-решений.
- Для 12 незащищённых capture reports локальная сводка показывает 9 `OK`, 3 `SKIPPED`; 214 Policy-решений не имели сохранённого LIVE snapshot, LIVE snapshots — 0, точных LIVE/Policy совпадений — 0. Это объясняет нулевые capture-совпадения в доступных отчётах, но не доказывает, что Policy не работал в игре: отчёт считает именно записанные и сопоставленные артефакты.
- Восстановление в рабочие Value/Policy-датасеты не выполнялось: нельзя доказать отсутствие дублей в существующих Value-папках, не открывая старые evaluation-артефакты. Восстановленных Value-решений: **0**. Восстановленных Policy-решений: **0**. Ни один существующий датасет не изменён.
- `fresh_holdout` не открывался; raw и derived outputs из 139 исключённых матчей не читались диагностическим скриптом. Эти 36 матчей не добавлены в split или `POLICY-DATA-PILOT-1`.

## Изменения

- Collector сохраняет raw один раз и записывает версию 2 состояния с независимым статусом, безопасным кодом причины, количеством и retryability для каждого из трёх процессоров.
- После рестарта повторяются только помеченные retryable-процессоры и только для их стадии. Value failure не блокирует Policy/Evidence. Успехи, дубликаты и ожидаемые skip-решения сохраняются независимо.
- Автоматически повторяются временные I/O, timeout и connection ошибки (и исключения, явно помеченные как retryable). Ошибки данных, `ValueError`/`RuntimeError`, отсутствие файла и отказ доступа не зацикливаются; их можно исправить и обработать безопасным ручным backfill. Существующая версия 1 state-файла читается.
- Fingerprint детерминированного отказа hslog сохраняется между перезапусками; изменённый/исправленный сегмент проверяется заново.
- Диагностические коды разделяют `SELF_UNRESOLVED`, `SELF_AMBIGUOUS`, `SELF_CONFLICTING_SIGNALS`, `SELF_CHOICE_OWNERS_AMBIGUOUS`, `DECISION_EVENTS_MISSING`, `RESULT_UNRESOLVED`, `POWERLOG_PARSE_ERROR` и `INVALID_PARSED_DATA`. В отчёты и консоль не добавляются имена, карты в руках или строки Power.log.
- LIVE остаётся fail-closed: несколько владельцев выбора, конфликт сигналов или отсутствие доказательства SELF не дают рекомендацию. Тесты проверяют это поведение.

Отклонены варианты: выбирать первого игрока, предпочитать mulligan одной руке при противоречии, считать одного controller доказательством клиентской стороны при иных конфликтах, или ослаблять проверку до «наиболее вероятного» SELF. Такие эвристики могут развернуть перспективу матча и испортить outcome labels.

## Backfill

Для одного raw-файла после ручной проверки его provenance и исключения из всех защищённых splits использовать новые отдельные каталоги:

```powershell
.\.venv\Scripts\python.exe .\scripts\process_completed_match.py `
  .\data\raw\collected\<reviewed-match>.log `
  --cards .\data\cards\standard_current_enUS.json `
  --value-output .\data\processed_real\collector_recovery_1 `
  --policy-output .\data\processed_policy_real\collector_recovery_1 `
  --evidence-output .\data\processed_evidence\collector_recovery_1
```

Не передавать команде всю `data/raw/collected`: CLI не читает evaluation lock-файлы и не исключает holdout. Выход recovery остаётся отдельным до отдельного provenance/split review. `process_completed_match(..., only={"value"})` позволяет повторить только отсутствующий результат из Python API; Policy и Evidence можно выбрать тем же способом.

- Не выполнялись обучение, изменение модели/Policy, обновление сплитов или merge.
