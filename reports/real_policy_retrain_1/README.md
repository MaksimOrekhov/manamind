# REAL-POLICY-RETRAIN-1 — расширенный реальный корпус

Дата: 2026-10-11. База: актуальный `origin/main` / `7d1500396efa359e2ddab524d5903c51fe292cf8`.
Ветка: `codex/real-policy-retrain-1`. **Обучение проведено, checkpoint сохранён. Вердикт: NO-GO для кандидата из-за серьёзной тактической регрессии.**

Имитационная cross-entropy улучшилась, но прирост Top-1 небольшой и статистически неоднозначный.
Новая Policy потеряла способность выбирать END_TURN в известном контроле без доказанного выгодного действия.
Рост силы игры не установлен. LIVE продолжает использовать исходную frozen v2.

## Гипотеза и протокол

Гипотеза до запуска: дополнительные реальные партии улучшают рекомендации без изменения архитектуры.
Основной baseline — frozen ML-2A PolicyNetworkV2, SHA-256
`044b9b50cd6b33912faf8dabe42d919305cb238a8d5cbfb1edf30bb3689d1e4d`.
Его исходный корпус: 21 матч / 736 решений; train 17/591, validation 2/85, test 2/60.
Дополнительные baseline: аналитический uniform legal и существующая узкая тактическая эвристика.

Повторно использован `scripts/train_real_policy.py`: scratch initialization, supervised cross-entropy по
точному `chosen_action_index`, AdamW, равные веса решений, существующий encoder/checkpoint loader.
Без fine-tuning исходных весов, Outcome-признаков, ValueNetwork, смены catalog/vocabulary или ManaEngine.
Архитектура совпадает с baseline: hidden 64, dropout 0.1, embedding 32, 1 187 vocabulary indices,
158 Policy state features и 163 entity features. State schema 16 / action checkpoint schema 4.

Один seed 42, lr 0.001, weight decay 0.001, batch 32, gradient clip 1,
max epochs 60, patience 8, min_delta 0.0001, один Torch CPU thread.
Это параметры ML-2A; изменены устройство CUDA и seed нового разбиения 20261011.
Гиперпараметры не подбирались. Конфигурация: [`configs/real_policy_retrain_1.json`](../../configs/real_policy_retrain_1.json).

## Зафиксированное разбиение и историческое использование

Разбиение по целым game_id фиксировалось до обучения. Внутри strata SELF class × final_result
используются пропорциональные квоты и SHA-256 порядок; test в первую очередь выбирался из партий,
отсутствовавших в реестре ML-DATA-REFRESH-2. Все три части непустые, взаимно не пересекаются и покрывают корпус.

| Split | Матчи | Решения | Победы / поражения | Priest / Warrior / DK |
|---|---:|---:|---:|---|
| Train | 32 | 1 175 | 17 / 15 | 26 / 5 / 1 |
| Validation | 7 | 281 | 4 / 3 | 6 / 1 / 0 |
| Test | 16 | 618 | 9 / 7 | 6 / 8 / 2 |

При 55 пригодных матчах сохранён тест из 16 и validation из 7; train увеличен с 17/591 до 32/1 175.
Два исходных v2 train матча оказались в новой validation, остальные 15 — в train.
Исходные validation 2 и test 2 также находятся только в development: validation 2 и train 2 соответственно.
Все 16 test матчей отсутствуют во **всех** исходных frozen v2 splits.

**Ограничение происхождения обнаружено после обучения:** старый реестр не включал более поздние локальные
ML-PILOT-1 и диагностические исследования. Дополнительный аудит сохранённых checkpoints/корпусов установил:

| Ранее известное использование | Train | Validation | Test |
|---|---:|---:|---:|
| ML-EVAL-0 | 10 | 2 | 0 |
| DATA-CHECKPOINT-1 и последующие диагностики на его корпусе | 32 | 6 | 15 |
| ML-PILOT-1 retrained v2 train / validation / test | 24 / 3 / 5 | 3 / 3 / 0 | 3 / 1 / 11 |

| Любое известное прежнее использование | 32 | 7 | 15 |

Категории пересекаются и не складываются. **15 test матчей / 578 решений уже просмотрены; только один
матч / 40 решений не имеет известного прежнего использования. Весь test не является независимым
исследовательским holdout.** Три test матча ранее обучали другие локальные кандидаты; их веса не использованы здесь.
Это не пересечение с train новой Policy или frozen baseline, но дополнительное ограничение исследовательской независимости.
Ранее опубликованные Action Outcome/target-quality диагностики на DATA-CHECKPOINT-1 также не считаются fresh evaluation.

После обнаружения ограничения split, конфигурация, эпоха и checkpoint **не менялись**.
Новых обучений, выбора seed по результатам test и переопределения тестовой выборки не было.
Исходный frozen manifest сохранён вместе с дополнительным usage audit; новая CLI позволяет явно
разрешить reused test и записывает его прежнее использование. Для будущих запусков нужен полный usage audit до freeze.

## Обучение и выбор checkpoint

RTX 5080, PyTorch 2.14.0+cu130, Python 3.12.10, NumPy 2.5.3;
`CUBLAS_WORKSPACE_CONFIG=:4096:8`, deterministic algorithms включены.
18 эпох, 147.67 секунды обучения/epoch evaluation. Минимальная validation CE выбрала **эпоху 10**;
восемь последующих эпох не улучшили её. Test начал оцениваться после сохранения и строгой перезагрузки выбранных весов.

## Источники, цели и склонность к END_TURN

Source agreement различает экземпляры в руке, позицию/тип публичного источника и героя.
Target agreement сравнивает side/kind/position/card ID и считает отсутствие цели ошибкой,
если фактическое действие targeted. END_TURN исключён только из source denominator.

| Измерение | Frozen: верных / решений (матчи) | Новая: верных / решений (матчи) |
|---|---:|---:|
| Тип действия | 440/618 (16), 71.20% | 429/618 (16), 69.42% |
| Карта / источник | 232/482 (16), 48.13% | 224/482 (16), 46.47% |
| Точная цель, unconditional | 56/183 (15), 30.60% | 67/183 (15), 36.61% |
| Цель при правильных типе и источнике | 37/69 (15), 53.62% | 46/63 (15), 73.02% |
| Сторона цели, когда обе цели присутствуют | 90/105 (15), 85.71% | 88/98 (15), 89.80% |

Ошибки стороны: 15/105 → 10/98, но отсутствующая target prediction выросла с 78 до 85 из 183.
Условные target знаменатели разные и не заменяют unconditional metric.

Action Outcome после выбора checkpoint нашёл точные локальные положительные эффекты на противнике
