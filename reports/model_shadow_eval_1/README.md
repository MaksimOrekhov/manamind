## Что измеряется (и что нет)

Совпадение рекомендаций модели с действием, которое игрок реально выполнил (восстановлено из Power.log существующим Policy-импортёром, без новой эвристики). Это **не** сила игры: действие игрока не считается оптимальным. Игрок видел Top-3 Policy v2 во время партий, поэтому у `policy_v2` есть «преимущество показа» — сравнение не полностью независимо.

## Сопоставление

Решение берётся, только если совпали: `match_id`, `options_id`, `state_hash` и полное упорядоченное меню (`menu_sha256` + хеш каждого действия). LIVE-`decision_id` (`match:seq:options:hash`) и Policy-`decision_id` (`match:options`) не сравниваются как строки.

## Результат (87 решений, 3 матча Demon Hunter)

Нетривиальные меню (≥ 2 действий, 80 решений) — основная таблица; «случайно» — ожидание при равновероятном выборе.

| модель | Top-1 | Top-3 | MRR | средний ранг |
|---|---|---|---|---|
| policy_v2 | 20,0 % | 50,0 % | 0,406 | 5,25 |
| retrained_v2 | 22,5 % | 57,5 % | 0,436 | 4,41 |
| policy_v3 | **31,2 %** | 56,2 % | **0,489** | 4,44 |
| случайно | 17,5 % | 48,0 % | 0,378 | — |

По матчам (нетривиальные меню, MRR): `96de69b7` (n=17) v2 0,335 / retrained 0,461 / v3 0,553; `2659ea1b` (n=53) 0,429 / 0,443 / 0,492; `1eb9927b` (n=10) 0,408 / 0,357 / 0,362.

**Ответ:** по MRR и Top-1 лучше всех совпадает с действиями игрока `policy_v3`, затем `retrained_v2`, затем `policy_v2`. Но преимущество **не доказано**: все три парных сравнения — `INCONCLUSIVE` (v3 против v2: только v3 верна в 19 решениях, только v2 в 10, точный тест знаков p = 0,136; MRR-разность +0,082, 95 % CI от −0,004 до +0,168, bootstrap по решениям, seed 20261013). В двух матчах из трёх v3 впереди v2, в маленьком (n=10) — нет. Решения внутри матча коррелированы, поэтому CI оптимистичен; матчей 3, игрок и класс один. Поверх этого policy_v2 получил преимущество показа, а policy_v2 лишь чуть выше случайного (Top-1 20,0 % против 17,5 %).

## Demon Hunter (87 решений)

- **HERO_POWER**: доступна в 51 решении, игрок использовал 6 раз (12 %). Top-1 = сила героя: v2 — 16 раз (13 переоценок, 3 недооценки), retrained — 11 (9 / 4), v3 — 4 (2 / 4). При ≤ 1 ман: v2 11 из 11, retrained 8, v3 3, игрок брал 2 раза; при 5+ ман: доступна 29 раз, игрок использовал 3 раза, ни одна модель почти не ставит её первой. Вывод: v2/retrained систематически переоценивают силу героя на малой мане; v3 — нет.
- **ATTACK** (игрок выбрал 28): точное действие v2 — 5, retrained — 4, v3 — 9. v2/retrained часто ставят на Top-1 другой тип (PLAY_CARD, END_TURN, HERO_POWER); v3 всегда предлагает атаку, но чаще берёт другого атакующего или другую цель.
- **PLAY_CARD** (игрок выбрал 36): точное действие v2 — 2 (в 9 случаях Top-1 — сила героя), retrained — 7, v3 — 12 (в 13 случаях Top-1 — атака).
- **END_TURN**: меню с альтернативами 80, игрок закончил ход 10 раз. «Модель завершает ход, игрок продолжает»: v2 4, retrained 2, v3 0; «игрок завершает ход, модель другое»: 4 / 5 / 8 (v3 почти никогда не предлагает завершить ход).
- **Цели** (игрок выбрал действие с целью 31 раз): точное v2 5, retrained 5, v3 9; верный источник, неверная цель: 1 / 3 / 3. Когда игрок и модель оба атакуют: игрок бил лицо 14 раз — v3 тоже в лицо 9 раз, в существо 5; игрок разменивал 14 раз — v3 в существо 12, в лицо 2.
- Примеры принципиальных расхождений (64 решения, в 19 все три модели разные) — в консольном отчёте и JSON (`model_disagreements`).

## Ограничения

Покрытие ограничено показанными игроку решениями; 3 матча одного игрока и класса; решения одного хода зависимы друг от друга; v2 видел показ. Результат не используется для переобучения и не меняет LIVE-модель; для вывода о силе игры нужны независимые матчи (ручной выбор не нужен — тот же инструмент на новых партиях).
