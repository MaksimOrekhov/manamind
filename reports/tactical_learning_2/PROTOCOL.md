# TACTICAL-LEARNING-2: протокол до обучения

Дата: 2026-10-11. Зависимость: исправленный генератор `a3b9b9de553869e15bdbf6ad4492f85b0caa8f3f`.
Исходный checkpoint SHA-256: `d2f18737be46bc1773997ec5106d1e30fdf2caaf645a3a7c8998956f092d6377`.

H1: 20% проверенных tactical-примеров улучшают сертифицированные свойства относительно real-only без существенной потери real imitation. H2: текущие Attack/Health вызывают правильную смену источника в парных вмешательствах. Baseline A: продолжение обучения только на реальных данных; также сравниваются frozen и initial.

Ровно два новых обучения, seed 42, одинаковые начальные веса и прежний whole-game real split. До 12 эпох и 600 секунд CUDA на кандидата, одинаковый общий early stop, 50 шагов по 32 примера. В каждом полном цикле B получает 20% tactical: 320 из 1600 предъявлений за эпоху; A получает 1600 real, B — 1280 real. Одинаковый пул real, различное количество его предъявлений является частью замены 20% бюджета. AdamW, LR 0.0001, WD 0.001, clipping 1.0. Архитектура, vocabulary и encoder неизменны.

Выбор checkpoint: минимальная tactical validation set CE среди эпох, где real validation CE не превышает initial +0.03 и Top-1 не ниже initial −0.03. При отсутствии допустимой эпохи — минимум real CE с отрицательным selection guard. Общая остановка, когда хотя бы один кандидат 4 эпохи не улучшает допустимую tactical CE, либо достигнут общий лимит эпох/времени. Control не участвует в выборе.

192 train, 32 tactical validation, 60 новых control (40 сертифицированных базовых, 12 position/ID-вариантов, 8 неоднозначных без gold). Семейства разделены комбинациями механик и числом источников/целей: например, train multi-lethal — один Taunt без щита героя, validation — один Taunt со щитом героя, control — два Taunt со щитом героя. Source-задачи используют соответственно 2/3/4 источника. Они проверяют перенос одной ограниченной задачи, а не независимые игровые правила. Меню перемешаны независимо от gold. Численные пары меняют только текущие Attack либо Health двух существ; они требуют смены источника. Position/ID-варианты требуют сохранения механического выбора с учётом множественных допустимых первых атак.

Gate до оптимизаторов проверяет все 284 строки: настоящий текст, тип, base metadata и механики по закреплённому каталогу; явные синтетические IDs; отсутствие подстановки неизвестных наблюдаемых эффектов; полное меню; независимую арифметику и точный Action Outcome; кодирование. Для multi-lethal integer proof и отдельный bounded Outcome replay дают одинаковые допустимые первые действия. Повторная проверка и хеши блокируют изменённые данные. Старые TL1 control используются только для проверки отсутствия нормализованных клонов, никогда для меток или выбора модели. Подготовка не ранжирует control моделью.

Положительная метка означает указанное ограниченное свойство (гарантированная победа, удаление цели с сохранением источника, положительный урон противнику без своего урона, END против чистого self-harm). Это не универсальный оптимальный ход. END доказан только в замкнутом меню: единственная альтернатива уничтожает свои существа, не затрагивает Immune-противника и расходует карту/ману.

H1 проходит при приросте B−A не менее 4 правильных базовых сертифицированных случаев. Safety: CE B ≤ min(A,initial)+0.05; Top-1 B ≥ max(A,initial)−0.03; Warrior Top-1 ≥ max(A,initial)−0.05; ноль новых сертифицированных ошибок относительно A и initial; оба selection guards положительны. H2 проходит при ≥3 из 8 пар с двумя верными ответами и сменой источника, с приростом ≥2 пары над A. GO требует H1, H2 и safety. Провал safety — NO-GO; H1/H2 противоречат друг другу либо один подтверждён — INCONCLUSIVE; обе без выигрыша — NO-GO. GO разрешает только новую независимую проверку.

Control открывается для предсказаний один раз после сохранения обеих выбранных моделей. После открытия никаких дополнительных fits, смены конфигурации или выбора другой эпохи. Старый real test и старые раскрытые tactical controls не оцениваются для подбора. Все checkpoints, JSONL, реальные идентификаторы и построчные logits остаются локально. Публикуются код, фиксированный протокол, агрегаты и отчёт в отдельной ветке без merge.
