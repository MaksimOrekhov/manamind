# Architecture review follow-up — 2026-09-30

## Confirmed observation gaps addressed

- RosettaStone observations previously exported minions but omitted Locations, even though the action bridge exposed Location activation. `PlayerObservation` now has a separate `locations` collection. Each item carries card metadata, remaining and maximum health, shared field position, cooldown, and activation state when the source can determine it. GameState enforces the seven-slot combined minion/Location limit. The value encoder and batching include separate SELF and OPPONENT Location zones; the policy prototype includes public Location counts, health, and known-ready counts.
- Power.log import now recognizes Location entities and the explicit `LOCATION_ACTION_COOLDOWN` tag. It does not claim the Location can currently activate because the log importer does not reconstruct the engine's full turn and card-requirement predicate. The encoding includes a known-state flag for activation.
- Power.log import populates `hero_power_ready` only when an observed hero-power entity has the explicit `EXHAUSTED` tag. Missing tag information remains `None`, which the existing encoder represents as unknown/neutral. RosettaStone continues to export its exhaustion state. This aligns the meaning of the feature; it is not a claim that available mana or all play requirements are encoded in this flag.
- `max_health` was checked and left unchanged: RosettaStone `Character::GetBaseHealth()` returns the `HEALTH` game tag; the importer uses the same tag while current health subtracts `DAMAGE`. A damaged entity therefore retains its pre-damage HEALTH value in both paths.
